# 四期：测试体系重构与跨平台 CI 实施计划

## 1. 目标与边界

按实际产品能力重新组织测试，补齐重要行为缺口，迁移有效回归，完成 Linux、Windows、macOS 的 GitHub Actions 与本地验证。实现依据为当前源码；不恢复早期路线中的未实现接口。三平台 workflow 已纳入本期落地范围，新增平台仍须经过真实构建、测试及失败修复，配置存在不代表验收通过。

Qt Test 负责用例、断言、数据驱动与 Qt 事件；CTest 负责程序级调度、标签、环境、超时及资源锁。选型依据是职责，不是旧测试的数量。禁止工具总数、Schema 镜像、逐字段复述及跨层重复业务矩阵。

## 2. 分支与提交

- 实施开始时基于 `main` 建立 `test-ci`，通过一个 PR 交付。
- 所有改动使用同一分支与一个 PR；基础设施、领域、协议、GUI 和 CI 修复按可审阅阶段提交。
- 提交采用 Conventional Commits；新增及修改的代码注释使用英文，只解释最终实现的必要约束；阶段文档使用中文。
- 早期创建 Draft PR，以 `pull_request` 实际运行分支内 workflow，不要求先合并。

## 3. 结构调整

1. 以产品能力建立[覆盖矩阵](test-coverage-matrix.md)，识别已有覆盖和缺口。
2. 测试目标按组件职责、共用 fixture 和进程运行条件划分；新增行为默认加入所属目标的 Qt Test slot 或数据行，不因新功能、历史 bug 或工具接口新增独立程序。每次测试程序执行只调用一次 `qExec`，用例发现与逐例结果由 Qt Test 维护；需要不同运行环境时由 CTest 显式注册条件，不对目标数量作约束。
3. 产品与领域测试共用 `EditorAutomationCore`，推理输入与校验共用 `EditorInferenceCore`，配置与语言设置共用 `EditorPreferencesCore`，独立 GUI 组件、编辑控制器及资源共用 `EditorGuiCore`；完整应用 GUI、音频资产和工作流复用链接这些组件的 `EditorRuntime`。生产源只在所属目标编译，测试支持层仅保留 fixture、必要服务替身与辅助设施，删除为重复编译生产源而引入的空 stub。
4. 提取进程沙箱，统一数据目录、配置、临时素材、超时与子进程所有权。
5. Qt 平台、路径和终止信号按当前系统适配，不把 CI 的 Linux 环境写成测试前提。
6. 对整个测试树统一整理为基础、参数、歌词、声线推理、配置、自动化运行时、编辑、应用服务、文档、音频资产、协议、进程及 GUI 等职责套件。当前结构形成 25 个程序，包含独立编译的推理 Provider 变体及 ICU 包装器；该数量是职责和运行条件划分的结果，不作为后续验收指标。完整职责见[测试大纲](test-outline.md)，历史入口迁移见[覆盖矩阵](test-coverage-matrix.md)。
7. 结合 Linux 与 Windows 本地覆盖率确认重要遗漏；补测应验证产品行为，不追求百分比或分支穷举。覆盖率口径及补测依据集中写入[测试报告](test-report.md)。
8. 将旧布尔场景函数及外层包装迁为直接 Qt Test slot；值比较输出实际与期望值，共享辅助断言保留调用位置。维持原有输入、严格相等或容差语义，并处理提前失败时的对象及环境清理。

用例源文件命名为 `tst_<snake_case>.cpp`。多文件套件使用 `test_main.cpp` 作为入口、`tst_<domain>.h` 声明测试类；单文件套件可在 `tst_` 文件内保留 `QTEST_MAIN` 或自定义入口，不强制拆出入口和头文件。fixture 和素材辅助保留表达职责的名称。一个套件只有一个 Qt Test 类和一次 `qExec`，需要分文件时按组件组织；不保留旧测试 QObject 包装，不增加通用用例注册表或逐函数 CTest 镜像。编译宏变体可共用同一套源码，各自独立构建和执行。

音频解码测试使用真实 Headless AppContext、AudioContext 和 AudioDecodingController，复用生产接线。套件共享应用生命周期，每例独立文档、通知和临时素材；完成后排空任务并恢复状态。文件访问 fixture 按例创建，文档与历史用例在用例边界清理历史，避免合并后依赖执行顺序。

## 4. 六类测试

基础数据与算法、编辑与应用状态、文档文件与异步工作流、自动化接口与 Connector、真实应用进程、界面组件与交互。详细职责见[测试大纲](test-outline.md)。

业务规则由所属层验证，接口层检查转换与授权，进程层验证产品装配。GUI 用例输入经过真实控件事件路径；主观显示观感和听感保留本地检查。

设置页检查真实输入、持久化及重开，声线混合对话框检查来源选择、权重拖动和确认/取消契约。缓存与离线调用以可观察状态、请求和结果验证，不能用任意循环次数或没有产品 SLA 的速度门槛替代行为断言；必要协议截止时间不受此限制。

## 5. CI 落地与调试

workflow 对面向 main 的 PR 和 main push 触发，使用矩阵分别构建完整 Editor、Connector 和测试；各平台使用 Qt 6.11.2 和 Debug 配置。

| 平台 | runner | vcpkg triplet | 覆盖率 |
|---|---|---|---|
| Linux x64 | `ubuntu-24.04` | `x64-linux` | GCC/gcovr 行与分支 |
| Windows x64 | `windows-2025-vs2026` | `x64-windows` | CI 执行测试；本地采集 MSVC 原生行覆盖 |
| macOS arm64 | `macos-15` | `arm64-osx` | 本期 CI 执行测试 |

每个平台按依赖、配置/完整构建、通用、协议/进程、offscreen 的顺序引导调试，最终执行 `ci` preset 的适用集合。`scripts/ci/bootstrap-vcpkg.py` 统一处理三个 triplet 的固定依赖引导；`bootstrap-linux.sh` 只委托 Linux 参数，不维护第二套安装实现。Windows 配置与构建复用 VS DevShell wrapper。

失败先区分下载/依赖、编译链接、运行时加载、行为断言、超时及隔离；检查平台专有路径、动态库、插件与进程行为，修复后先定向复验，再在新提交上完整执行。各矩阵项独立保留结果，某个平台通过不替代其他平台验证。旧 run 的重跑不验证新代码。最终验证各依赖路径的空缓存与正常缓存命中，不缓存整个构建树。

Linux 完整构建成功后，即使测试失败也收集 coverage，供定位缺口；三个平台均保留诊断产物。执行版本和失败项由运行日志、测试产物及 PR 保留，不能把失败采样作为通过证据。

## 6. 覆盖率采集与解释

提供独立 `coverage` preset，在 `build/Coverage` 构建完整应用与测试，避免插桩产物污染普通测试构建。Linux 使用 GCC/gcovr 统计行和分支；Windows MSVC 使用完整调试信息及 `/PROFILE` 链接，通过 `scripts/tests/collect-msvc-coverage.py` 调用原生静态插桩收集器，包含测试拉起的应用进程。

统计范围为本项目生产源码，排除测试、第三方及生成代码。Windows 按源码文件和行号对多个程序/模块的命中取 OR 后去重，不把同一行在不同测试程序中的副本重复计入分母；该采集器不提供可与 GCC 对比的分支统计，不把其导出格式中的占位分支值当作覆盖率。

Linux CI 集合、Windows 本地通用/原生集合和显式声库资源集合分别记录运行条件。本地提供声库后实际执行资源用例，等待语言处理与分段准备就绪，再验证手动推理任务完成及有效音频输出。资源客户端与无资源 Headless 用例共用协议传输；发现的问题由最小受控回归或真实资源流程验证，不靠启用自动推理或扩大超时掩盖。覆盖贡献按功能路径分析，不直接比较不同平台、编译器和资源集合的总百分比；精确采样结果保留在产物。

## 7. 交付与审查

测试实现、三平台 CI 与本地规定集合验证完成后提交两份报告并 mark ready。首次 ready 自动审查；此后的代码/构建配置修改推送后发布 `@codex review`。真实问题修复、验证、回复并 resolve；误报说明理由。

受审代码完成相应验证，并获得 bot thumbs-up 或明确无问题结论，才完成目标。仅修改文档且不影响构建或测试时，无需重新执行或等待 CI。最终认可保留在 PR 和交付答复，不为抄回报告另造提交。

具体提交号、运行 ID、逐轮结果和原始日志留在 PR、本地产物及 Actions artifacts，不写入阶段文档。不建设长期同步或文档生成机制。
