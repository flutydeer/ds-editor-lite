# 四期实现报告

## 1. 交付概况

本期交付测试体系的职责重组、重要行为补测及跨平台基础设施。Linux、Windows 和 macOS CI 构建完整 Editor、Connector 与测试，执行普通、GUI 和内置声库流程。覆盖率仅在 Linux CI 的独立 Coverage 步骤生成；Windows/macOS 使用普通 Debug 构建执行全部适用测试，本地原生及 LLVM 采集入口继续保留。验证范围与实际结果见[测试报告](test-report.md)，详细执行证据和审查结论统一保留在 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187)。

本报告记录本期交付设计及验收事实，适用至本期发布。逐次用例数量、执行耗时、依赖具体版本和运行结果由源码及 CI 产物承载，不在报告中维护逐提交快照。

## 2. 测试结构与生产复用

测试按基础数据与算法、编辑与应用状态、文档文件与异步工作流、自动化接口与 Connector、真实应用进程、界面组件与交互六类组织。Qt Test 维护用例、断言、数据行和真实 Qt 输入；CTest 负责标签、环境、超时、互斥及结果汇总。一个测试程序对应一个 CTest 注册项，具体用例只在 Qt Test 中维护；跨 Host 场景归入共用进程套件，并使用其 offscreen 环境，不另建函数清单镜像。

`lite_tests` 聚合测试目标，`tests` build preset 同时构建 Editor、Connector 和全部测试，原先独立的 ICU wrapper 测试也纳入统一入口。本轮全树整理形成 25 个程序，包含共用源码的两个推理 Provider 编译变体；这是职责、依赖和运行环境的划分结果，不作为后续数量指标。完整职责及历史迁移去向分别见[测试大纲](test-outline.md#9-套件职责与程序划分)和[覆盖矩阵](test-coverage-matrix.md)。

新增行为默认加入所属 Qt Test 类的 slot 或数据行，同一程序只有一个实际测试类和一次 `qExec`，不保留旧类包装或通用注册表。用例文件采用 `tst_<snake_case>.cpp`；多文件套件使用 `test_main.cpp` 入口及 `tst_<domain>.h` 声明，单文件套件在 `tst_` 文件内保留 `QTEST_MAIN` 或自定义入口，fixture 辅助保留语义名称。基础、参数、歌词、声线推理、配置、应用服务、文档、音频、协议和进程各自收拢相邻职责；GUI 分为组件、编辑交互、渲染、原生桌面和完整应用接线。应用 GUI 共享 AppContext，各用例独立创建和清理所需控件；其余局部 fixture 同样在用例边界复位，不依赖执行顺序。

曲线变换、时间线、音频锚点、参数支持、主题、声线混合、缓存、推理配置和歌词规则的旧布尔测试函数迁入直接 Qt Test slot，保留原输入与容差契约。数值比较提供实际值与期望值；确需共享的辅助断言统一保留调用位置。提前失败通过局部所有权或 fixture cleanup 清理预览对象、曲线及环境变量。

生产实现按依赖边界共享：

- `EditorAutomationCore` 承接模型、编辑服务、Facade，以及歌词规则、整片段剪贴板和曲线 JSON 编码等可共享实现；应用与领域测试链接同一目标。
- `EditorInferenceCore` 承接推理任务输入转换、通用输入模型与 Speaker Mix 校验；应用与输入转换测试共用生产目标，测试不再用空方法满足链接，也不需要完整 GUI Runtime。
- `EditorPreferencesCore` 承接通用配置、自动化及推理选项、语言设置和客户端配置；生产运行时与配置、GUI 测试共用这些实现。
- `EditorGuiCore` 承接编辑视图和撤销控制器、AppStatus、视口与滚动逻辑、菜单、字形、几何、波形、标题栏及应用资源。四个组件级 GUI 套件与 Editor 共用该静态库，不再各自列出和重复编译生产源。Qt 元对象分别编译，使独立组件不会因聚合 moc 被迫链接应用控制器；静态资源在运行时和主题套件入口显式初始化。
- `EditorRuntime` 承接剩余应用实现、翻译及完整运行时装配，链接上述生产组件；Editor、音频资产、应用工作流和应用 GUI 测试复用这一实现。
- `AutomationTestSupport` 承接 fixture。外部服务、时序和设备条件使用必要替身，不复制业务逻辑。

整片段与音符复制共用曲线编码，TrackController 与领域测试共用粘贴位置准备逻辑。生产库缺失的 ICU、提取模块依赖补在所属库自身，避免为每个测试追加链接补丁。接口测试移除了工具总数、完整工具清单和 Schema 字段镜像；少量跨层场景比较业务结果、错误和副作用。

音频资产套件使用真实 Headless AppContext、AudioContext 和解码控制器，删除空 AudioContext、DocumentWorkflowController 方法及文档测试中无用的 AppContext specialization。应用生命周期可以共享，文档、历史、任务、通知及临时素材仍在每例边界清理；测试替身只承接实际需要控制的外部条件。

## 3. 行为补测与产品修复

产品能力复查与覆盖率采样共同确定补测范围，除整理存量外，补齐了以下重要行为：

- DSPX 编辑内容往返，以及丢弃保存分支后的 dirty 状态。
- 整片段参数复制、跨轨粘贴、歌词拆分规则和推理结果 Apply/Drop/Defer 门控。
- 真实钢琴窗绘制、音符拖动及撤销；歌词后移菜单检查连音、整套文字属性和手工音素清理，钢琴键盘检查滑奏与隐藏后的 note-on/off 释放。剪贴板覆盖复制/剪切/粘贴，轨道右键粘贴另检查悬停预览、取消和提交位置一致。
- 无需声库的短 WAV 导入、真实 Editor 导出任务、输出解码与文档状态检查；实际导出在中途进度回调取消，检查旧目标文件保留、暂存文件清理和混音器状态恢复。
- 离线导出后原先打开或关闭的混音器状态恢复，复用 `TestApplicationWorkflows` 中的 Headless AppContext。
- 轨道声线变化向实际 SingingClip 传播、自有声线隔离及切回继承，替换遮蔽传播行为的空 stub。
- 导出对话框的格式与文件名预览、轨道来源与混音选择，以及取消后重开恢复配置；复用小型 WAV，通过真实 Export 按钮进入生产导出器，检查完成提示、进度、Close 关闭、任务清理及进度窗口释放。通过真实键盘和鼠标检查界面、设置及文件副作用。
- 默认参数编辑器与轨道视图的真实鼠标路径：绘制参数、Shape/Scale 选区变换、基于真实推理基音的 Legacy 音高调制和片段拖动，检查预览、范围外数据保留、单次提交、Escape 取消及撤销恢复。轨道头部另验证名称提交/取消、静音/独奏与撤销同步，以及颜色悬停预览、取消恢复和点击提交。
- 外观设置页从真实侧栏进入，经鼠标开关和键盘编辑提交，检查内存配置、配置文件及重新打开后的值；遵循即时保存契约，不把关闭设置页当作撤销。
- 音频/MIDI 页在无播放设备时验证增益/声像转换、控件同步、生成器/包络和参考音高的关闭提交与重开；合成预览组件使用受控音频回调验证采样率变化后的包络时长、实际 PCM 启停和音源清理。
- 声线混合对话框通过真实标签选择和分隔线拖动改变来源及权重，检查确认返回的配置，取消后重开恢复初始草稿，且不意外修改预设或文档。
- 运行中手动重启推理：暂停真实 duration worker 后替换流水线，检查旧任务释放、替换任务终态和队列清理；该回归无需安装声库。
- 关闭自动推理时的显式完整推理：验证本次手动请求可进入声学阶段，完成后恢复后台等待策略；使用实际声库完成推理、声码器与 WAV 导出闭环。公开状态查询另通过暂停真实 Pitch worker 检查阶段与任务作用域关联，完成阶段及其他片段不误关联，实际成功后清除活动任务关联。
- 批量参数锚点及轨道操作、相邻曲线合并、动态声线关键帧、片段分割和语义搜索，检查结果、批量原子性及撤销。
- DSPX 往返保留音素偏移、固定及动态声线配置，资源暂不可用时保留保存的声线来源；LRC 的整秒、小数秒、多时间戳及失败重载。
- 实际应用适配器的预设存储、歌词规则生效、MIDI/DSPX 批量导入及失败回滚；轨道视口经真实拖放将音频导入现有及新增轨道，检查一次提交和撤销；音频检查混音、静音、WAV/FLAC 及受控播放。自定义导出预设经同名更新、落盘重读后实际输出 PCM16 WAV，再验证删除及原配置恢复。
- 填词预览与导入、MIDI/DSPX 导入配置、自动化和推理设置、缓存清理、动态声线编辑、音素对话框及主窗口搜索等真实 GUI 输入路径；声线预设经界面保存、选择、修改后标记和删除，包与音频资源页面验证搜索详情及取消/重定位后的解码和撤销。
- 内置中英文双声线声库的 G2P、完整推理、音频导出、缓存复用，以及声线和速度变化后的重算；不以非空回退结果替代实际发音检查。
- 内联歌词及读音经双击进入真实编辑层，检查提交、取消、音符间导航和撤销；音素边界拖动检查偏移提交，波形使用实际推理音频并验证切换片段后不接纳过期加载结果。
- SeekBar 的实时/释放提交、键盘步进与复位，以及 Fader/Pan 的预览、释放和随后外部更新；区分控件预览与实际值变化。
- 公共批量导入的选项、权限和失败策略，以及源文件变化、授权撤销后的计划复验；公共填词验证实际文字、连音及语言选择。真实音频批量解码检查原子失败、部分成功、取消后的重新执行及一次撤销；公开路径确认/重定位经 Registry 和生产 Host 准备，检查路径、格式、哈希、真实解码及单次提交/撤销，损坏文件和提交前取消不修改工程。
- NativeDesktop 中的 Tracks RHI 跨轨拖动和裁边，以及条件音频设备配置/公开播放和 MIDI 回环输入；设备用例的条件不足与执行失败分别报告。
- 实际读音/音素任务在编辑期间暂存结果，结束后应用，文档换代或片段删除后丢弃；ApplicationWorkflows 复用同一内置声库，快照门控与实际完成接线分开验证。
- 主窗口面板最大化/隐藏与恢复、分离后重新嵌入、嵌入设置阻断后台快捷键及恢复焦点；LogWindow 接收真实总线的跨线程消息，检查过滤、按显示顺序复制及清空。
- DocumentWorkflowController 的保存决策使用外部 UI 回答替身，验证生产状态机、busy、真实保存文件与工程替换；按文件工作流记账，不作为真实保存弹窗的输入覆盖。
- Tagger 的实际规则编辑、Apply 生效与无效正则拒绝，Splitter/Tagger 在编辑、启停和重开后保持规则 ID；Null RHI 补已有音符移动/裁边和音高锚点，公共参数查询补范围、降采样预算和锚点保真。

上述后续补测记录实现范围，实际结果需随所属完整集合验收，不能沿用此前三平台通过记录作为新增行为已通过的依据。

补测和跨平台执行确认并修复了保存点悬空导致的误判、歌词空匹配重复前缀、公开播放调用被设备错误弹窗阻塞、退出响应发送前连接销毁，以及导出后对原先关闭的混音器调用 `open(0,0)` 等问题。修复保留原有行为断言；具体根因及验证方式见测试报告。

真实声库执行还发现，重建流水线直接销毁旧状态对象，会同时丢失驱动任务队列的完成接线。替换流程改为先取消该片段的任务，让已有队列取消路径建立清理回调，再销毁旧流水线。受控回归先在未插桩构建中复现队列停滞，再验证替换任务正常进入终态。

另一处缺陷是手动推理沿用了仅考虑自动推理和播放状态的声学准入，关闭自动推理时会停在等待状态。修复为目标流水线携带本次请求许可，variance 更新及声学缓存探测共用准入判断；进入 Ready 或取消时清除许可，不改变用户设置。受控生产状态用例验证后台等待、手动放行和完成后的策略恢复，真实资源流程验证完整输出。

推理任务还消除了准入与实际重置之间的排队间隙：完成版本/阶段/资源检查、创建任务记录及安装取消和终态接线后，在同一事件轮次重置并入队，避免后台结果先推进版本导致已接受任务立即冲突。模型工作仍由异步状态机执行，真正过期请求和后续结果应用门控继续生效。

GUI 测试通过真实控件事件检查界面和业务状态，覆盖快捷键焦点、菜单、分隔条、视口及生产动画等组件。纯数值或几何检查与真实输入路径分开，不以调用 Facade 后检查模型替代 GUI 测试。

Connector 缓存及离线调用不再用任意重复次数和缺少产品 SLA 的耗时阈值判断正确性。改为检查缓存查询不增加上游请求、Editor 快照变化使缓存刷新、删除与保留的工具得到相应结果，以及离线调用的明确状态与错误。协议自身的超时、背压和有界停止仍按各自契约验证。

自动化编辑模式转换补齐参数 Shape/Scale 与音高调制，避免将有效 GUI 状态回报成默认模式，或在设置入口拒绝已支持的操作。输入与输出复用模式契约，既有协议用例检查实际传入的枚举和状态读回，并保留工程版本不变的断言。

macOS 执行发现任务终态回调转移后的资源释放缺陷：移动 `std::function` 不保证原对象为空，保留的历史记录可能继续持有后台许可。转移时显式清空原值，并保留锁外调用；既有生命周期用例检查保留终态历史时完成回调的捕获资源已经释放，接口用例检查取消后可继续准入。

Windows 无 GPU 环境暴露初始化早退后的等待问题：外层设备检查失败时，共享推理运行时未收到尝试结束通知，包扫描继续等待会话并阻塞退出。完成通知收敛到共享方法，外层所有返回路径及关闭操作均唤醒等待者。ApplicationWorkflows 通过已有 Provider 和设备查询配置，在独立子进程中复现真实失败，检查包任务及时失败及正常析构；没有新增产品开关。

后续工作流补测还确认了动态声线编辑会重建未修改关键帧的身份、未安装声库时 DSPX 读回丢弃声线来源、LRC 时间缩放及失败重载状态错误等缺陷。相应修复位于生产模型转换和编辑路径，测试保留原本应成立的行为。推理替换在延迟销毁前停止旧状态机，并在新状态机异步启动前同步发布 Pending，避免旧回调污染和沿用旧 Ready 提前成功。资源客户端仅在服务端明确拒绝版本冲突时刷新版本并有界重试。

对于已解析声库移除了末尾声线的工程，转换器按过滤前来源数解码保存权重，保留剩余来源的相对比例。文档往返用例同时覆盖包不可用与来源减少两种兼容行为；测试仅替换外部声线元数据查询，文件解码、筛选、归一化及再次保存均复用生产实现。

规则页的新草稿原先没有稳定 ID，首次 Apply 后页面继续发送空身份；Splitter 的详情收集及 DTO 转换还会丢弃已有 ID。同一规则再次应用因此被当作新规则。两页在新建草稿时分配现有格式的 ID，后续收集和转换保留身份；原 GUI 编辑/启停与重开流程增加身份不变断言，实际验证随完整集合进行。

AudioPage 在驱动初始化失败后仍解引用空 driver；设备列表刷新入口现按实际条件禁用设备、缓冲和测试控件，保留其他设置，并在切换失败后复用同一刷新。SynthHelper 的采样率通知补齐 decay 时长重算，与 attack/release 一致。AudioExporterConfig 的复制构造及赋值移到私有共享数据类型完整的实现文件，修复公开头调用方的编译边界，保留原共享及写时复制语义；这些变更及新增用例仍须经过完整集合验证。

macOS 无 MIDI 服务时，设备枚举和打开可能抛出 RtMidi 异常。生产 MIDI 系统集中处理设备访问失败，启动保留无设备状态，切换失败保留原设备。RtMidi 的 CoreMIDI 客户端 helper 还将可能抛出的调用错误声明为 `throw()`，服务创建失败时直接 terminate，绕过应用已有的异常处理。项目覆盖端口移除该错误异常规格，并在失败判断前释放临时名称对象；Linux 在 manifest 中显式声明 ALSA 特性与依赖，Windows/macOS 保持各自原生后端。独立 C++ 验证确认异常可传播到已有 catch，实际应用修后的平台行为仍由进程集合验收。

另移除已经没有产品接线的旧 G2P/PseudoSinger 设置页及 TrackSynthesizer，相关分母变化单独解释，不计作新增测试命中。

真实主窗口场景暴露了通知接收者的生命周期问题：应用控制器持有窗口裸指针，窗口销毁后历史通知仍可经控制器访问旧窗口。窗口改为直接接收历史通知，连接随窗口销毁自动解除；外观设置回调同样绑定窗口上下文，删除不再需要的窗口指针及转发层。搜索用例保留完整窗口的创建、交互和销毁路径。

搜索窗口关闭后保存声线预设，还揭示了工具栏私有对象未随视图释放的问题：`ClipEditorToolBarViewPrivate` 没有 QObject 父对象，也没有析构回收，遗留的 General 设置通知访问了已销毁的歌手下拉框。私有对象现在归属工具栏，由 QObject 所有权同步释放并解除连接；既有搜索与预设保存流程继续验证这条生命周期，不新增独立测试目标。

RHI 控件销毁私有状态时，其子控件销毁可能重入外层控件的事件处理。显式释放私有状态，并在事件入口发现状态已释放时委托基类，避免访问正在销毁的状态；保留 NativeDesktop 中真实 RHI 控件的输入、帧提交及析构路径，不用跳过清理规避崩溃。

受控播放暴露了 Talcs 在跨循环终点时重复累计已读取长度，导致下一音频块跳过采样的问题。项目覆盖端口在原版本上修正剩余长度计算；独立使用同一音频源的修前/修后执行确认位置和 PCM 连续性恢复。

离线导出还暴露了预读模式切换的位置同步缺陷：关闭预读没有停止后台读取并恢复逻辑位置，直接读取又没有推进包装源的位置，使首次导出的起点依赖预读进度。Talcs 补丁在缓冲模式切换时清理预读，在直接读取后推进位置；同一独立验证程序确认关闭和重新启用预读前后的 PCM 与位置连续，Windows 原混音、静音及格式用例也已在修后通过，保持原断言。覆盖端口保留完整原配方以符合 vcpkg 的端口解析方式，产品只链接一份 Talcs；共享端口提供等价修复后移除该项目覆盖。

## 4. 跨平台与资源条件

`lite_register_test` 集中配置测试类别、offscreen、原生桌面条件、资源条件和 Windows 动态库路径。通用测试不依赖 CI 环境变量，不无条件指定 Windows Qt 插件；原生桌面用例保留必要互斥。常规 Windows/MSVC 测试不要求覆盖率工具。

`ProcessFixture` 为场景分配数据根、配置、访问根和素材，只管理自身创建的进程与文件。成功清理，失败保留参数、退出状态、协议记录和 stdout/stderr。配置、日志、缓存和单实例身份复用统一数据路径，`DSEL_TEST_DATA_ROOT` 仅在测试构建生效，不扩展产品 CLI 或公开工具。

可执行文件路径来自 CMake target，stdio 阻塞接收端采用跨平台替身。重启进程使用独立输出文件，并具备各平台的存活、所有权和清理实现。Qt Test 的 Windows 日志进入可捕获输出，资源跳过与失败细节可以汇总。

Connector 的本地服务名使用短 UUID 名称，失败时输出实际系统错误，避免 macOS 临时目录与场景描述共同超过 Unix socket 路径长度。连续滚动用例显式指定触摸板设备，使事件身份与预期手势一致。macOS 应用部署保留 FFmpeg 端口的私有相对路径，在 Qt 部署前复制对应配置的私有库目录，实际进程测试负责验证应用装配。

普通进程场景在套件启动配置中显式使用 CPU、空声库搜索路径并关闭自动推理；资源与初始化失败场景提供自己的配置。通用进程设施原样写入调用者配置，不隐式覆盖这些条件。

macOS 的原生窗口效果只在 Cocoa 后端操作 NSView，offscreen 保留普通 Qt 窗口行为。独立可执行的运行时测试通过 `RuntimeResourcesFixture` 取得实际 Editor 的歌词配置，在 macOS 另取得 bundle 插件目录并优先加载同一 bundle 的 Frameworks；资源路径覆盖复用已有测试构建开关，正式产品不识别该测试环境。缺失或空的内置规则在初始化时报告失败，避免按测试程序位置寻找资源导致文件系统异常中止。

GUI 初始化在 offscreen 后端统一使用 Fusion 样式。WindowsVista 样式依赖真实原生窗口句柄，Qt 的原生主题路径不适用于 offscreen；实际 Windows 执行出现的 `OpenThemeData` 错误与该约束一致。样式选择收敛在 `AppEnvironment`，应用和测试共用同一初始化，原生桌面继续使用对应平台样式。

macOS 部署先放齐插件、语言资源及 FFmpeg 私有依赖。歌词配置、插件清单、模型和词典归入 bundle 的 Resources，原位置保留包内相对链接，以兼容第三方插件的相邻资源布局，避免签名工具将数据当成代码。FFmpeg 私有库保留原有相对依赖，由应用的构建搜索路径声明私有目录，使 Qt 能通过 SONAME 链接解析库的版本化 install ID；预编译库不额外增加加载命令。随后由 Qt 官方工具统一处理依赖和签名；插件作为附加二进制提供，使其依赖相对自身位置解析，结束后检查完整签名。旧的手工 Qt 路径修补脚本已移除。

仓库内置 `voicebank-fixture.zip`，由 CMake 解压到当前构建目录，ModelResources、ApplicationGui 和 ApplicationWorkflows 共用默认资源；不要求在运行测试时安装训练框架。包使用独立的 `ci-fixture` 身份、两条人工声线及中英文小型词典，八个自制 ONNX 计算图满足各生产阶段输入输出要求，输出低幅度确定性音频，不包含真实训练权重或特定真实声库主体信息。生成代码暂留忽略的 build 目录，资源说明见[README](../../../src/tests/resources/README.md)。

显式配置外部声库时覆盖默认资源；指定后的加载或执行失败报告失败，不回退内置包。Windows 曾使用本机真实声库完成 CPU 推理、声码器和 WAV 导出，补充真实模型兼容性证据。内置资源不需要播放设备，也不能替代 GPU、真实模型质量、实际设备播放和听感检查；GAME/RMVPE 不在本期扩展范围。

设备行为已提供条件用例：输出设备自动发现或按名称指定，使用静音素材检查实际缓冲配置、落盘及播放回调；MIDI 通过显式配置的专用回环检查生产输入与合成器的 note-on/off 结果。没有可用输出设备或未配置 MIDI 回环时逐例 QSKIP；指定条件或已枚举设备初始化、打开、执行失败报告 FAIL。用例只清理自身资源，不安装虚拟驱动，不建立硬件组合矩阵，配置方式见[测试计划](test-plan.md#3-运行条件)。

常规 Headless 与声库测试共用 Native HTTP 请求、超时及响应校验，补齐实际协议要求的响应类型协商；资源用例提供显式语言和任务作用域，并等待异步 G2P/分段完成后再启动手动推理。共同传输路径在无声库测试中也执行，避免资源客户端独自偏离接口要求。

## 5. CI 与覆盖率采集

CI 使用 Linux x64、Windows x64 和 macOS arm64 矩阵，runner 均采用 latest；每个平台分段完成环境、依赖、配置、完整构建、测试和产物收集。Linux 使用 `coverage` preset 和 `build/Coverage`，测试后由独立 Coverage 步骤生成报告；Windows/macOS 使用普通 Debug `tests` preset 和 `build/Tests`，不运行覆盖率采集器。面向 `main` 的 PR 更新及 `main` 推送触发验证；Qt、vcpkg 和依赖版本由 workflow、manifest 及 overlay 声明。统一依赖引导脚本按 triplet 执行，Windows 构建复用项目 DevShell wrapper。各平台独立保留结果，构建或测试失败均传播失败退出码并收集诊断材料。普通 GUI 使用 offscreen，原生桌面集合在 Linux 使用 Xvfb，在 Windows/macOS 使用原生桌面。

缓存限于 Qt 和 vcpkg 包，不复用整个 CMake 构建目录。vcpkg 缓存键关联 runner 镜像、Qt 和依赖声明，回退缓存仅提供候选包；每轮仍执行 install，由 ABI 决定复用或重建。镜像升级后的新 ABI 包可以写入新键，避免旧键精确命中阻止保存。失败构建使用独立 partial key 保存已完成包，完整成功缓存使用独立键。缓存哈希包含共享端口和项目覆盖端口，Talcs 补丁变化同样触发实际依赖核对；此前 wolf-midi 的临时覆盖已经在上游修复后移除。

Qt 和 vcpkg 缓存按平台及 triplet 隔离。验收分别核对依赖缓存未命中的完整安装路径，以及实际命中后仍执行 install、完整构建和规定测试的路径；Linux 另有依赖升级时复用兼容包并重建变化依赖的证据。逐平台结论见[测试报告](test-report.md#42-缓存路径)，不以删除缓存或命中提示代替完整执行结果。

Linux GCC/gcov 插桩由显式选项启用，独立 Coverage 步骤使用测试已产生的数据，gcovr 统计项目生产源码的行与分支覆盖，排除测试、第三方及生成文件。`merge-lines` 合并同一源码行的模板实例，既有数据重算的口径变化不计为新增命中。逻辑覆盖以接近或超过 90% 为方向，不设机械 CI 门槛，不为达标排除整目录或填充 Schema 断言，也不重复运行测试生成报告。HTML、JSON、CSV 进入 Linux CI 产物；逐文件 CSV 同时输出到日志，便于直接定位缺口。三平台均保留 JUnit、完整测试日志和环境信息，失败素材包含测试产物范围内的隐藏暂存文件。

Windows 按需本地分析保留独立 `coverage` preset 和 Visual Studio 原生静态插桩，构建时提供 PDB 与 `/PROFILE`，关闭与其不兼容的 Edit and Continue。采集器在执行前插桩，覆盖 Editor/Connector 子进程并恢复原二进制；项目脚本按源码文件和行合并多个程序中的重复统计。Windows 与 Linux 的编译代码、行映射不同，分别报告，不直接把百分比差值视为新增覆盖；Microsoft 输出中的占位分支比例不作为分支覆盖率。

建设中的 Windows 专项采样表明，实际采集耗时主要来自大型原生程序的静态插桩，相关证据继续保留。最终 Windows CI 采用普通 Debug 全量测试，不要求 Microsoft 覆盖率收集器；需要进一步分析时再运行本地采集。测试程序和异步任务自身的截止时间保持独立。

macOS 按需本地分析保留 LLVM 源码插桩入口，按进程及模块输出原始 profile，再合并为 HTML、LCOV、逐文件 CSV 和原生分支汇总；最终 macOS CI 使用普通 Debug 全量测试，不进行 LLVM 插桩。Windows/LLVM 共用生产源码过滤、CTest 程序发现和源码行去重逻辑，保留测试输出与实际退出码。建设中已取得的跨平台专项采样仍可用于分析缺口，其运行条件和计数由相应产物承载。

LLVM 正式 LCOV 导出不再启用 `-dump`：该诊断选项会把调试文本写入标准输出，与 LCOV 数据混合并导致解码失败。采集保留标准错误、输入对象清单和原始 profile，先前的逐函数诊断独立留在产物中；不通过忽略无效字节修补报告，也不把报告输出污染误记为原始覆盖数据丢失。

## 6. 取舍与文档边界

测试目标按组件依赖和执行环境划分，后续可按共享 fixture 和依赖收益继续调整，不要求维持当前数量。推理门控使用真实任务快照验证结果应用规则，实际模型输出交给资源用例。主观视觉、实际听感和设备组合不建立像素或硬件矩阵。

默认钢琴窗和轨道视图走 Legacy/QGraphicsView，真实输入用例覆盖默认路径。实验 RHI 钢琴窗及轨道另在 NativeDesktop 中使用 Qt Null 后端，经过实际音符绘制/移动/裁边、音高锚点插入与取消、片段跨轨拖动和裁边，检查预览、提交/取消、命中、撤销重做及帧提交；该方式验证 CPU 准备和命令路径，不宣称验证 GPU 着色器、像素观感或全部图形驱动行为。

本期文档是实施与发布验收材料，覆盖率详细计数和逐次运行记录留在 [Actions](https://github.com/flutydeer/ds-editor-lite/actions/workflows/tests.yml) 产物中，不建设长期文档同步或自动生成机制。最终通过依据包括规定测试与 CI、真实审查问题的处理，以及 Codex bot 对受审版本的认可；动态审查状态和完成证据统一保留在 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187)。
