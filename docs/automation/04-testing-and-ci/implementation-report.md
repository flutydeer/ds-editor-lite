# 四期实现报告

## 1. 交付概况

本期交付测试体系的职责重组、重要行为补测及跨平台基础设施。Linux、Windows 和 macOS CI 构建完整 Editor、Connector 与测试，执行普通、GUI 和内置声库流程。覆盖率仅在 Linux CI 的独立 Coverage 步骤生成。Windows/macOS 使用普通 Debug 构建执行全部适用测试，本地原生及 LLVM 采集入口继续保留。验证范围与实际结果见[测试报告](test-report.md)，详细执行证据和审查结论统一保留在 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187)。

本报告记录本期交付设计及验收事实，适用至本期发布。逐次用例数量、执行耗时、依赖具体版本和运行结果由源码及 CI 产物承载，不在报告中维护逐提交快照。

## 2. 测试结构与生产复用

测试按基础数据与算法、编辑与应用状态、文档文件与异步工作流、自动化接口与 Connector、真实应用进程、界面组件与交互六类组织。Qt Test 维护用例、断言、数据行和真实 Qt 输入。CTest 负责标签、环境、超时、互斥及结果汇总。一个测试程序对应一个 CTest 注册项，具体用例只在 Qt Test 中维护。跨 Host 场景归入共用进程套件，并使用其 offscreen 环境，不另建函数清单镜像。

`lite_tests` 聚合测试目标，`tests` build preset 同时构建 Editor、Connector 和全部测试，原先独立的 ICU wrapper 测试也纳入统一入口。本轮全树整理形成 25 个程序，包含共用源码的两个推理 Provider 编译变体。这是职责、依赖和运行环境的划分结果，不作为后续数量指标。完整职责及历史迁移去向分别见[测试大纲](test-outline.md#9-套件职责与程序划分)和[覆盖矩阵](test-coverage-matrix.md)。

新增行为默认加入所属 Qt Test 类的 slot 或数据行，同一程序只有一个实际测试类和一次 `qExec`，不保留旧类包装或通用注册表。用例文件采用 `tst_<snake_case>.cpp`。多文件套件使用 `test_main.cpp` 入口及 `tst_<domain>.h` 声明，单文件套件在 `tst_` 文件内保留 `QTEST_MAIN` 或自定义入口，fixture 辅助保留语义名称。基础、参数、歌词、声线推理、配置、应用服务、文档、音频、协议和进程各自收拢相邻职责。GUI 分为组件、编辑交互、渲染、原生桌面和完整应用接线。应用 GUI 共享 AppContext，各用例独立创建和清理所需控件。其余局部 fixture 同样在用例边界复位，不依赖执行顺序。

曲线变换、时间线、音频锚点、参数支持、主题、声线混合、缓存、推理配置和歌词规则的旧布尔测试函数迁入直接 Qt Test slot，保留原输入与容差契约。数值比较提供实际值与期望值。确需共享的辅助断言统一保留调用位置。提前失败通过局部所有权或 fixture cleanup 清理预览对象、曲线及环境变量。

复杂轨道及片段的插入重试复用复制流程的内容 fixture，包含音符与音素、绘制和锚点曲线、独立声线及本地化元数据、音频时间锚定与波形缓存。两种插入入口共用数据行，验证重试返回原创建对象、曲线或声线内容变化产生幂等冲突，并保持单次提交、完整撤销和重做。内容由生产快照及编辑服务准备，不直接调用指纹辅助函数或逐字段维护测试矩阵。

ApplicationWorkflows 的入口及自有子进程模式集中在 `test_main.cpp`。项目保存、单文件加载、批量导入和外部转换器失败场景放在 `tst_project_files.cpp`。各文件继续共用同一个 Qt Test 类、AppContext 生命周期和测试程序，按业务职责维护用例。

原生 RHI 框选的按下、移动及释放通过真实画布的 Qt Test 事件派发。Qt Test 的按钮状态由框架模拟。等待实际 `frameSubmitted` 信号期间暂缓原生用户输入，释放后立即处理延迟事件，避免系统鼠标坐标覆盖模拟拖动的预览。需要读取系统游标的边缘滚动仍保留原生游标操作，框选业务结果、帧提交及撤销断言不变。

锚点框选和分组拖动复用实际 RHI 画布 fixture，单曲线和跨曲线共用数据行。选择与预览不修改工程。取消保留所有节点，提交后只移动选中节点并保留相对位置、身份及未选内容，形成一次编辑，撤销和重做继续更新画布。这些场景不公开控制器私有状态或增加仅供测试的产品接口。

领域锚点的批量编辑共用同一四节点曲线，删除后不足两个节点时检查曲线被清理，形成一次修改。完整工程撤销恢复原内容，曲线及节点身份保持，重做再次清理，不另建退化曲线的测试程序。

原生音频设置用例先准备编辑窗口，关闭设置页后等待焦点回到编辑窗口及下拉弹窗结束，再析构控件。设备选择、缓冲区及采样率均继续经真实下拉框输入，设置快照在主窗口初始化完成后建立。

音频驱动启动取消在隔离子进程中直接使用正式 `AudioDriverManager` 和实际选用的驱动，不为驱动级断言重复启动整套应用及推理服务。完整应用关闭和设备播放仍由对应场景验证。无异步启动后端的条件在父用例报告跳过。子进程保留独立截止时间，记录实际耗时及退出状态，超时只终止本用例创建的进程并保留输出。

视口的填满下限和倍率限幅集中到 `EditorViewportScale`，由 Legacy 的 `TimeGraphicsView` 与 RHI 的 `EditorViewportController` 共用。计算使用未缩放的内容尺寸，不把播放指针留白当作内容，也不从已失效的倍率反推内容宽度。Legacy 自动填满、滚轮和程序缩放复用同一约束，零长度唱段不会产生无穷大倍率，换回正常工程时原钢琴窗仍可使用。窗口尺寸变化时分别调整两轴，避免开启横轴填满后阻断纵轴调整，继续复用已有倍率边界计算。

共用触控控制器在新接触按下时停止松指惯性，不再等待拖动或轻触判定。导航场景使用生产时钟和真实触控事件观察松指后继续滚动，再按住时视口稳定，保持工程、选择与历史。恢复可见位置后继续原音符移动及撤销。

视口动画场景同时承接触控板的滚动和原生捏合完整事件流，检查松手后的惯性及新手势中断。系统配送 ScrollMomentum 时，应用不在 ScrollEnd 再启动一段惯性。各数据行共用视口准备和最终状态断言，不另建计时器或滚动实现。

单例注册表对查询、注册及清空使用同一互斥锁，支持应用启动时后台推理初始化与主线程服务注册并行。锁仅保护注册表，不延长返回对象的存活期。宿主仍在销毁服务前结束使用它们的任务。基础套件直接复用生产注册表验证并发注册期间查询结果保持有效。

生产实现按依赖边界共享：

- `EditorAutomationCore` 承接模型、编辑服务、Facade，以及歌词规则、整片段剪贴板和曲线 JSON 编码等可共享实现。应用与领域测试链接同一目标。
- `EditorInferenceCore` 承接推理任务输入转换、通用输入模型与 Speaker Mix 校验。应用与输入转换测试共用生产目标，测试不再用空方法满足链接，也不需要完整 GUI Runtime。
- `EditorPreferencesCore` 承接通用配置、自动化及推理选项、语言设置和客户端配置。生产运行时与配置、GUI 测试共用这些实现。
- `EditorGuiCore` 承接编辑视图和撤销控制器、AppStatus、视口与滚动逻辑、菜单、字形、几何、波形、标题栏及应用资源。四个组件级 GUI 套件与 Editor 共用该静态库，不再各自列出和重复编译生产源。Qt 元对象分别编译，使独立组件不会因聚合 moc 被迫链接应用控制器。静态资源在运行时和主题套件入口显式初始化。
- `EditorRuntime` 承接剩余应用实现、翻译及完整运行时装配，链接上述生产组件。Editor、音频资产、应用工作流和应用 GUI 测试复用这一实现。
- `AutomationTestSupport` 承接 fixture。外部服务、时序和设备条件使用必要替身，不复制业务逻辑。

整片段与音符复制共用曲线编码，TrackController 与领域测试共用粘贴位置准备逻辑。生产库缺失的 ICU、提取模块依赖补在所属库自身，避免为每个测试追加链接补丁。接口测试移除了工具总数、完整工具清单和 Schema 字段镜像。少量跨层场景比较业务结果、错误和副作用。

文本框、可编辑下拉框和两种表达式数值框共用标准文本菜单转换，保留 Qt 动作及子菜单的所有权和接线，按动作名称分配图标，修复只读模式下按位置分配造成的图标错位。组件用例通过实际菜单复制、粘贴、撤销和只读复制，原有数值步进用例继续验证附加动作。

路径列表内联编辑在关闭编辑器时检查模型保留的值，避免将 Escape 丢弃的空草稿当作删除已有目录。持久索引跟随所编辑条目，普通提交、清空确认及空区域创建继续使用同一 Qt 编辑路径。组件数据行验证既有目录及空草稿的提交与取消，不复制编辑提交逻辑。

路径列表测试从条目与视口的交集选择点击位置，空白区域创建沿用可见横坐标。长临时路径可以让文本行宽超过视口，测试不再假设整行中心可见。排序、删除及内联编辑仍通过真实鼠标和键盘事件完成。

参数绘制在现有提交与撤销场景中加入真实触控数据行，与鼠标绘制及原始曲线描摹共用预览、范围外保留、单次提交和 Undo/Redo 断言。触控期间改变手指绘制设置，验证在途手势仍按开始时的模式完成。退出用例时恢复设置并释放未完成的输入。

参数中断场景承接鼠标绘制、右键局部擦除和笔橡皮端数据行，复用同一曲线及范围外保留、工程与历史断言。笔失活中断后可以再次擦除，借用的擦除工具在取消和释放后均恢复普通绘制。输入配送与其他笔场景共用 tablet 事件辅助。

音符绘制通过鼠标和普通笔尖两条数据行共用预览、提交、选择及 Undo/Redo 断言。普通笔尖行投递受控的 tablet/鼠标事件对表示外部输入，接触中的侧键额外按下与释放保持原预览，平台菜单副本被消费，最后正常释放只提交一次。

笔悬停状态按实际 Qt 平台后端选择读取方式：Windows 原生后端使用指针消息，其他后端使用 Qt tablet 事件。悬停场景通过真实钢琴窗验证侧键和橡皮端提示、松开侧键及离开感应范围后的光标恢复，保持工程与历史。Windows 原生驱动的标志读取仍按其平台边界验收。

编辑器的应用级快捷键在 Qt 查找快捷键前按当前窗口切换作用域。日志等其他窗口保留自身快捷键，文本输入和弹窗继续由原有输入保护处理。日志用例复用真实主窗口和设置服务，验证延迟创建、隐藏后重开保留筛选和记录，再执行完整行及消息复制。不另建日志或剪贴板业务实现。

音频导出的文件计划和覆盖确认共用一个真实 Dry Run 窗口检查辅助，验证空轨道选择、重名目标、模板警告及修正后恢复。批量工程导入复用既有加载素材和失败策略数据行，区分受理前拒绝与受理后任务失败，并保留原子性、警告和完整撤销断言。钢琴键盘在同一滑奏流程中检查悬停、按下与离开的即时绘制变化，不维护截图基线。

公开单文件加载与批量导入共用文件内的真实解析暂停夹具。打开和导入在解析已启动后经公开任务入口取消，批量场景在首项准备完成、第二项正在解析时取消，均检查原工程及历史保留、后台释放后的晚到结果不提交，以及同一请求重新执行成功。沿用原加载和撤销断言，不增加测试程序或加载器替身。

公开推理任务在完整编辑提交及撤销重做后检查已准入乐句是否仍属于当前工程。删除片段即使为撤销保留对象，也会结束对应公开任务，避免 worker 已清理而任务仍停在运行中。跨轨移动不结束任务，因为检查发生在完整操作之后。受控启动用例共用真实 duration worker，验证移动、撤销重做、取消与删除后的终态，以及晚到结果不改变工程和历史。准备夹具仅屏蔽声线选择通知，片段重建保留生产通知，使音频侧同步释放旧引用。

MIDI 发布用例将原先长函数中的组合断言整理为共用准备、独立报告的数据行，检查创建、替换、授权拒绝、取消及并发目标出现。批量音频失败策略复用原有素材和业务断言，经公开 Registry 进入实际解码与提交，补齐接线而不复制一套跨层矩阵。音素边界在同一已准备乐句上分别编辑并撤销，复用语言和推理初始化。

填词用例用数据行区分预览网格与 LRC 文本输入，共用目标音符、取消及撤销断言。文件选择取消保留原文字，导入后收起预览仍可直接提交，界面选项按正常路径保存。轨道边缘拖动验证真实计时器持续推进预览及结束后停止。音素拖动复用同一视图验证修改工程速度后的边界同步。

公开 MIDI 发布共用受控渲染与释放逻辑，检查成功写入、取消、渲染期间撤销目录授权和文档换代，并验证终态、准入释放及暂存文件清理。公开音符插入检查手工音素的无时序/完整时序读回，部分偏移使批量插入整体拒绝。动态声线查询检查完整权重、关键帧身份、移动和旁路，公开权重更新保留位置、身份和其他关键帧，撤销恢复原快照。参数范围缩放的准备步骤通过公开绘制入口生成曲线，检查样本、步长、一次提交及撤销重做，再继续原缩放断言，减少重复初始化。

公开推理任务改按实际乐句身份关联状态查询，替代请求范围字符串的严格相等比较。轨道任务可以通过其片段范围查询，阶段汇总不明确时不误报单一任务。尚未启动的等待阶段显示为待重新计算，已有任务尚未执行到的阶段显示为排队。原有任务关联场景复用为目标轨道含两个片段，并保留无效目标整批拒绝和其他轨道隔离。音频解析重试场景同时检查公开候选路径的授权过滤、去重和只读查询。

阶段重置同步失效推理状态和声学就绪标记，避免结果已清空而查询仍回报就绪。既有真实推理场景继续从公开接口重置目标片段的音高，验证上游结果、其他片段及用户历史保留，下游结果清除并显示待推理。随后实际重新推理恢复输出。用例结束时先释放工程和任务，再清理音频缓存。

推理运行中修改采样步数通过正式设置服务进入已有状态机重启路径。用例暂停实际 Pitch worker 后修改设置，检查旧任务取消、新任务输入及签名更新、重新生成有效结果，同时保留用户音符与撤销记录。复用工作流套件和内置声库，不另建重试实现。

公开取消后允许流水线暂时缺失，后续参数编辑共用同一恢复入口，按表现力、音高或方差参数的依赖从 Pitch、Variance 或声学缓存探测重新运行，保留无关上游。停止标记在实际任务入口生效，避免 Qt 异步启动在处理停止前创建旧任务。回归复用原参数依赖场景，检查真实公开任务取消、正确下游重算、任务清理、其他片段保留及撤销，不另建取消后的业务实现。

音频资产套件使用真实 Headless AppContext、AudioContext 和解码控制器，删除空 AudioContext、DocumentWorkflowController 方法及文档测试中无用的 AppContext specialization。应用生命周期可以共享，文档、历史、任务、通知及临时素材仍在每例边界清理。测试替身只承接实际需要控制的外部条件。

轨道菜单的音频导入复用文件选择与成功解码断言，增加解码器拒绝打开后的错误提示、工程和历史保留、任务释放及同一路径重试。外部解码器替身与音频资产用例共用，错误提示仍由真实控制器和控件产生，不替写导入逻辑。

文件菜单和资源检查共用主窗口 fixture。缺失音频的原 GUI 用例改从实际 DSPX 打开进入，由应用自动建立资源检查窗口，再复用取消、重定位、解码及撤销重做断言。不另铺同一业务流程的界面副本。

GUI 和原生套件共用剪贴板快照，在套件开始保存原内容、结束时恢复。每个复制粘贴场景仍自行建立来源并经真实操作写入剪贴板，消除原生数据行之间反复读取和恢复用户多格式内容的重复准备。

菜单悬停辅助同步游标并通过真实 QWindow 发送输入。下拉框触控场景通过键盘打开选项列表，将选项输入与 Qt 的开启鼠标释放保护分开。声线预设的 More 菜单使用异步 popup，动作仍直接连接原业务槽。窗口曝光和激活后检查实际悬停项，再以连续的 Qt Widgets 按下、释放完成点击。同步确认框的应答器保留至实际点击和确认结束，仅识别本窗口的弹窗。失败记录输入阶段及窗口状态，并清理本例拥有的对象。保存、取消、选择、初始化及删除的业务断言保留。

钢琴窗 fixture 在输入前等待实际窗口曝光、激活及焦点。内联文字场景的双轻触同步配送到真实 Qt 触控路径，两个接触之间不处理无关原生输入。长按释放同时检查现有计时器是否到期，回调尚未配送时仍保留菜单请求。正常与延迟回调的数据行共用拖选、菜单后继续输入及画布恢复断言。已有触控诊断用于报告未交付的输入，工程、历史及结束后继续绘制的断言保持不变。

已有音符的原生 RHI 夹具统一按窗口曝光、前置、激活、首帧、焦点的顺序准备输入。Cocoa 的窗口激活请求不会将非活动应用带到前台，因此输入夹具使用 Qt 的 `raise()` 后再请求激活。主窗口隐藏编辑区后重新打开，以及面板分离和重嵌入后，同样准备实际窗口再请求焦点。失败断言报告本窗口曝光、应用状态、模态窗口、弹窗和焦点控件，保留实际焦点与编辑结果的检查，不伪造活动窗口或延长超时。

RHI 内联歌词和发音共用原有触控编辑场景，在拖选过程中配送系统 TouchCancel，再重新按下、选字和释放。检查取消被实际画布接收、编辑框仍可用、文档与历史不变，随后继续原有提交、导航、取消和撤销断言，不直接调用文本接管的私有方法。

RHI 切分场景按正常鼠标与拒绝笔擦除后恢复鼠标两行组织，共用原音符、量化切分、帧、撤销和选择断言。笔行通过 Qt tablet 和带笔设备的移动事件进入实际画布，检查禁止光标、拒绝输入不改变工程或历史、离开感应范围后鼠标仍可切分。Windows 原生后端从系统指针消息读取悬停标志，合成 Qt 悬停行明确报告不适用，Qt 事件后端由本地对应平台及实际 CI 验证，不伪造监视器的私有状态。

其他轨道音符参考由同一生产数据源供 Legacy 和 RHI 使用。编辑交互套件验证宿主及同轨排除、绝对时间排序、模型变化与通知、显示开关、删除及撤销和文档换代，保留几何场景验证可见区外开始的长音符、视口缓存及颜色对应的条形范围。应用 GUI 经实际外观开关检查参考条显示和隐藏，再在参考条上绘制宿主音符并撤销，外轨内容保持不变。原生 RHI 只补其装配职责，检查参考更新与开关触发实际帧，以及输入仍编辑宿主，不重复数据源的完整业务矩阵。

控件触摸转换在共享 TouchClaimFilter 中保留独立的重放设备状态。Qt 构造鼠标事件时会更新所用设备的触点 0，复用原触摸设备会破坏后续移动与释放的路由。独立状态保留触摸来源判定，又不改写原流。系统取消不带触点时，使用最近认领的局部和全局位置结束按下，先通知目标取消，再走原释放路径。轨道鼠标和触摸重排共用身份、控件/画布顺序、完整工程快照、单次提交与撤销断言。组件取消检查从大滚动场景提取为单独的 Qt Test 数据行，避免重复整套滚动准备。

音符绘制场景共用鼠标、普通笔尖和选择工具双击新建的数据行。双击使用完整点击、双击、拖动和释放，复用生产 DrawNoteHandler 的量化与编辑事务。预览不修改工程、一次提交、模型与场景同步及撤销重做的断言共用，不增加绘制实现或独立测试程序。

公共声线预设生命周期复用已加载的实际声库验证目录不可用后的恢复。接受空目录后，等待生产解析器将片段歌手标记为 Missing，再检查旧歌手请求被拒绝且预设、工程及历史保留。恢复原目录并等到 Resolved 后，同一请求继续成功，身份和比例不变。原有应用、查询、删除及撤销流程继续执行，不另建声库解析或预设业务替身。配置不变性直接比较生产预设服务快照，避免为断言绕行另一份 JSON 编码。

声库目录的多语言场景共用包内阶段与依赖包声码器的数据行。依赖包由同一微型声库副本生成，只声明声码器且不声明歌手，主包按正式依赖引用该阶段。真实扫描验证歌手解析状态和跨包声码器的音高控制能力，继续执行原显示、版本刷新、查找、文档及历史保留和目录恢复断言。全部阶段跨包时上游能力报告缺失，以及独立声码器共享时的错误警告另记为已知依赖问题，不伪造报告或增加平行解析器。

填词预览用例共用自动、逐字和自定义分隔的数据行，通过实际键盘切换模式及输入分隔符，检查字段可见性、设置持久化、预览内容与后续导入。原有预览文字编辑、确认和取消、未选音符保留及撤销重做继续复用，自动和自定义的已知词保持真实 G2P 结果断言。逐字输入检查字符拆分，不要求任意单字符都在声库词典中。

公开主题和界面语言更新复用该窗口 fixture，验证实际设置适配器、主题/翻译管理器、已打开控件和磁盘配置之间的接线。写盘失败保留原状态，恢复后同一请求成功。这与既有设置页面鼠标/键盘用例分担接口接线和控件交互职责。

协议设置场景在原默认语言更新中加入按语言组织的默认歌词，检查 Registry 转换后的实际设置和公开查询返回值。MCP HTTP 原响应限制场景复用同一服务，以单请求准入上限覆盖无效信封、外部处理器异常和超限响应，失败保留请求 ID，后续普通请求证明准入释放及服务可用。三个结果共用请求和恢复检查，不复制不同层的业务校验矩阵。

音频批量导入的原故障策略场景增加受理后源文件消失的数据行。共享线程池屏障确保真实授权和解码探测已完成，再删除临时输入，复用原子拒绝与尽力提交的完整工程、版本、历史、解码结果和警告检查。声学及声码器损坏的原进程资源场景继续查询正式推理状态，验证失败原因和活动任务清理，修复后恢复就绪，再执行原 PCM 导出检查，不手工赋值推理状态或重复创建失败流程。

公开设备选择复用 ApplicationServices 的设置服务夹具，可选注入外部枚举快照，默认仍使用原有回退。音频与计算设备共用预验证、提交、重复请求及完整设置保留断言，候选筛选和设置合并继续执行生产 Facade。用例检查不可用驱动或设备、设备不支持的格式，以及 GPU 稳定身份与索引匹配。有效选择只保存一次并报告计算设备的重启字段，GPU 不再可用时仍可切回 CPU，无需为这些确定性行为打开真实设备。

推理设备页的异步查询通过可选函数承接外部设备枚举，默认继续使用正式 DirectML/CUDA 查询。受控结果用于验证显存筛选、按保存设备 ID 恢复而非沿用列表索引、实际选择与配置落盘，以及切换 CPU 后丢弃旧设备结果。真实硬件枚举场景继续保留。页面和筛选业务不另建替身，未编译 GPU Provider 的平台按实际能力报告不适用。

工程内容对比统一复用正式 DSPX 编码。转换器将内存编码与文件发布分开，保存仍执行原有校验和原子写入。共用测试快照不写文件，也不改变保存点。旧 `AppModel::serialize()` 经轨道的简化序列化遗漏片段，不能单独证明音符、曲线和声线未改变。相应断言改用真实持久化内容，源码中的旧入口仍保留。对象身份、revision、历史和运行状态继续独立验证。

主线新增的触控和笔输入测试按同一职责组织整合。触控状态机、笔意图及工具路由归入 EditorInteraction 的直接 Qt Test slot。控件触控占用、重排手柄及指针提示框归入 GuiComponents。原先各自的测试程序入口及重复源码编译被移除，纯输入状态机实现由 EditorGuiCore 与产品共用。触控手柄保留命中和显示上下文断言，不复制边框绘制常量。

触控滚动惯性单独报告执行条件，平台缺少有效物理尺寸时明确跳过。夹具让松指事件携带最后一段移动，避免终点停顿被 Qt 正常识别为停止。失败附带实际物理度量、输入时间及速度轨迹，仍检查释放后滚动。关闭触控滚动只要求保留 Qt 原有接收属性，并通过真实拖动验证页面不滚动。控件拖动、取消、重建后重新占用及祖先滚动隔离仍执行。原生捏合按主线的两轴缩放行为检查模型锚点和动画中断，旧 Direct Manipulation 配置随产品移除，不保留平行输入实现。

系统长按适配器的 Windows 消息类型及常量与原生过滤器放在同一平台分支，非 Windows 保留共享触控控制器及自身长按行为。平台适配不通过伪造 Windows 类型或屏蔽测试来满足编译。

Windows 原生覆盖率采集器及其子进程使用本轮产物目录内的独立 TEMP/TMP，插桩备份和测试临时文件由本轮运行持有。采集与测试的失败均保留真实退出码和原始日志，不因测试程序全部通过而吞掉采集器错误。报告区分测试断言失败与采集过程失败。

触控事件接线在真实钢琴窗中验证。绘制提交、平台取消和第二指接管共用场景，检查预览、文档、事务、历史及再次编辑。导航与选择、系统提升鼠标过滤及长按菜单的配送另按各自行为组织。原生 RHI 绘制在已有数据行增加触控输入，复用相同模型、历史和实际帧断言。

内联歌词的触控接管复用同一钢琴窗，双轻触进入真实文本框后检查拖选、平台取消、松指前提交及长按菜单。提交前工程不变，结束后画布输入与撤销恢复正常。笔侧键点击另外检查生产菜单配送、平台副本抑制及键盘菜单保留，不复制 Qt 菜单项清单或文字布局。

画布的共享触控控制器在释放前核对已有长按截止时间，到期但回调尚未配送时先进入原长按处理，再完成释放。这样保留对象菜单与空白延期选择两条既有路径，晚到回调由原手势状态拒绝。无需增加计时器或时钟。原 GUI 长按场景增加受控延迟数据行，沿用菜单时机、选择保留、工程与历史以及事务清理断言。

RHI 的内联编辑和音高笔划复用原场景新增指针数据行。触控与鼠标共用歌词、发音、导航及撤销验证，笔橡皮在绘制工具下临时擦除，结束后通过实际鼠标绘制检查工具恢复。音符连续擦除也复用原场景增加 DrawNote 下的笔橡皮行，共用预览、Escape 取消、原子提交、撤销与帧断言，随后鼠标仍可正确选择恢复的音符。Legacy/RHI 测试的 tablet 事件发送集中到小型 TestSupport 辅助，继续进入各自生产控件，不另建手势或编辑业务实现。

RHI 轨道跨轨移动复用已有场景增加触控数据行。未选片段上的拖动只导航，轻触选中后才可以编辑。系统取消保留工程、版本及历史，下一次拖动共用鼠标场景的预览、一次提交、实际帧和撤销重做断言。指针发送只在输入方式上分支，不复制移动业务或新增测试程序。

RHI 歌词悬停夹具先同步本用例的系统游标和待处理移动，再向实际画布送入最终无按钮 Qt 鼠标事件，避免将无按钮 QWidget 移动是否派发和窗口事件队列作为断言前提。提示框内容、离开隐藏、工程及历史保持仍按实际控件检查。失败时附带已有输入轨迹。

钢琴窗的窗口失活、触控取消和笔擦除中断共用指针清理：丢弃预览及事务，同时清除失去释放事件的按下状态。笔输入恢复已通过真实 tablet 事件验证。擦除临时借用的处理器随后归还原工具，不让被中断的操作写回或使下一次输入被忽略。橡皮端及侧键共用擦除场景，不支持擦除的工具保持原工程。

RHI 音符裁边的数据槽同时承接鼠标和触控。触控先经实际轻触选中，再从音符实体之外的左右手柄开始，预览、局部时间与长度、一次提交、事务释放、实际帧及撤销后的命中恢复共用原断言。导航场景同时执行时间尺、键盘和画布滚轮、捏合、横纵滚动条及单指双轴平移，检查文档与历史保留。滚动条的另一轴按其整数逻辑像素精度检查，避免将整数偏移与浮点视口严格相等混用。

公开音素时序编辑复用现有音素和有效语言场景，通过 Registry 设置偏移数组并重置，检查音符身份、原始时序、音素名称和单次版本变化，逐步撤销恢复完整工程。再继续原音素名修改和重置流程，接口层只验证转换与接线，领域及真实 GUI 仍负责详细编辑行为。

参数整体替换的失败检查复用原 Draw/Anchor 混合内容，在曲线仍存在时拒绝无效几何、重叠锚点曲线和超出编辑值域的输入。小型请求循环共用完整工程、曲线和节点身份、版本及撤销入口的保留断言，随后一次撤销恢复初始工程。预验证、往返及重复 no-op 的原流程保留，不铺参数类型和错误字段矩阵。

## 3. 行为补测与产品修复

歌词搜索的界面和公开接口共用 `NoteAutomationFacade` 查询。正则表达式的前缀与完全匹配在编译模式时约束整个表达式，使可选分支能正常回溯。修复接口遗漏合法完整匹配、界面将部分匹配列入结果的问题。界面每次输入只查询一次，模式切换在选中新项后刷新，保留大小写、无效表达式恢复及结果导航的真实输入验证。

工具提示通过悬停、说明文字更新、离开和再次进入验证显示内容、快捷键及释放。更新说明原先只将旧标签移出布局并解除父对象，留下无人持有的控件。现在在移除布局项时释放旧标签。生命周期断言允许控件复用或释放，要求显示内容更新且没有脱离所有权的标签。

缓存清理工作流使用实际推理输出，验证文档换代后由缓存探测恢复的 WAV 及输入仍受当前工程保护。释放文档后旧缓存可清理，无关用户文件保留。音频设备条件用例复用真实设置页和播放流程，通过下拉框修改设备别名、缓冲与采样率，检查设备实际状态、配置持久化和工程不变。内置英语 G2P 另同时转换词典词及词典外词，执行产品随附模型的输入输出适配。

同一设备用例继续经主窗口按钮和空格快捷键验证播放、暂停、停止及三种播放头策略，检查位置文字、按钮状态和工程历史。受控音频回调在工作线程完成暂停后暂不交付通知，先停止再恢复播放，验证旧通知不会覆盖新请求。这部分不需要硬件。修复已暂停后停止未回位，以及晚到暂停通知再次打断播放的问题。

公开推理的阶段重置共用已准备的真实声库、工程及请求流程。方差重置保留上游音高，只重新请求方差和声学，音高重置继续执行原下游重算。两种入口共用状态失效、实际结果、其他片段及用户历史保留检查，沿用原取消和状态关联场景，不为每个阶段复制整套推理流程。

主窗口轨道编辑快捷键通过真实焦点和按键验证全选、复制、粘贴、剪切、删除及撤销。文档换代期间视图发出的选择更新会被生命周期门控拒绝。现在在新文档恢复 Active 后统一清除旧轨道及片段选择，避免残留轨道索引使粘贴无效。新场景先建立旧工程选择，再换代并继续编辑，不依赖其他用例留下的状态。

产品能力复查与覆盖率采样共同确定补测范围，除整理存量外，补齐了以下重要行为：

- DSPX 编辑内容往返，以及丢弃保存分支后的 dirty 状态。

界面语言用例复用产品翻译资源和真实下拉框，完整窗口及已打开设置页随语言切换更新，检查设置值、选区和已有历史保留。填词场景继续使用搜索返回的身份修改目标词语言。音频路径重试将直接会话赋值改为真实另存工程并重新发现素材。推理输入用同一旋律检查连音分组、间隙辅音提前量和首尾填充，既覆盖正常音符组合，也保持测试快速独立于模型。

扩展用例随完整产品构建和所属测试集合验证，Linux CI 独立采集覆盖率，Windows 保留推送前的本地完整测试与覆盖采样。受测版本和具体结果由对应产物记录。资源条件不足的设备用例按实际条件报告跳过，具体边界见测试报告。

覆盖分析区分有效运行路径与无产品入口的遗留实现。旧全局 SeekBar、没有切换入口的 Uniform 键盘模式及当前协议拒绝的旧片段草稿字段不新增测试，源码保留。不以绕过私有状态或放宽公开协议的方式命中它们。

补测和跨平台执行确认并修复了保存点悬空导致的误判、歌词空匹配重复前缀、公开播放调用被设备错误弹窗阻塞、退出响应发送前连接销毁，以及导出后对原先关闭的混音器调用 `open(0,0)` 等问题。修复保留原有行为断言。具体根因及验证方式见测试报告。

真实声库执行还发现，重建流水线直接销毁旧状态对象，会同时丢失驱动任务队列的完成接线。替换流程改为先取消该片段的任务，让已有队列取消路径建立清理回调，再销毁旧流水线。受控回归先在未插桩构建中复现队列停滞，再验证替换任务正常进入终态。

另一处缺陷是手动推理沿用了仅考虑自动推理和播放状态的声学准入，关闭自动推理时会停在等待状态。修复为目标流水线携带本次请求许可，variance 更新及声学缓存探测共用准入判断。进入 Ready 或取消时清除许可，不改变用户设置。受控生产状态用例验证后台等待、手动放行和完成后的策略恢复，真实资源流程验证完整输出。

推理任务还消除了准入与实际重置之间的排队间隙：完成版本/阶段/资源检查、创建任务记录及安装取消和终态接线后，在同一事件轮次重置并入队，避免后台结果先推进版本导致已接受任务立即冲突。模型工作仍由异步状态机执行，真正过期请求和后续结果应用门控继续生效。

GUI 测试通过真实控件事件检查界面和业务状态，覆盖快捷键焦点、菜单、分隔条、视口及生产动画等组件。纯数值或几何检查与真实输入路径分开，不以调用 Facade 后检查模型替代 GUI 测试。

RHI 轨道视口复用原生轨道夹具，实际滚轮输入验证时间尺横向缩放、画布平移和轨道列表纵向缩放。列表与画布双向滚动及逐轨键盘定位保持偏移和行高一致，提交新帧但不改变工程或历史。钢琴窗保留原有捏合及滚轮接线用例。

跨曲线锚点场景还通过实际端点选择和悬停进入合并预览，预览提交帧但不改变工程。点击后只产生一次合并，保留各节点身份、位置和值，撤销恢复原有两条曲线。

普通参数绘制和取消场景使用数据行覆盖描摹与右键局部擦除，共用鼠标移动夹具。描摹取原始曲线而非鼠标高度，原始数据保留。局部擦除保留范围外数据，取消后可重新提交。完整工程快照同时检查撤销与重做后的内容恢复。

推理后端的界面选项与公开候选统一复用 `ExecutionProviderUtils::availableInBuild`，修复非 Windows 将 DirectML 误报为可用的问题。已有设置流程验证不支持的后端被拒绝、真实设备选择及无设备回退。声码器 CPU 选项复用设置持久化和稍后重启的流程，重开页面保持所选值。

自定义标题栏的系统按钮由原生桌面套件验证，主窗口与分离面板共用输入检查。最大化、还原和最小化后，在同一分离面板验证隐藏底部后通过页面入口恢复、隐藏轨道后恢复两面板，再通过关闭按钮重新嵌入。当前页、分隔条状态和文档保留。页面布局事件完成后才记录待恢复尺寸，不以像素截图或固定屏幕大小作为断言。

DSPX 打开等待声库元数据的现有四种完成结果共用真实主窗口，扫描失败时实际点击确认窗口的继续或取消按钮。移除该场景对 UI 回答替身的依赖，仍控制外部扫描就绪状态，继续检查等待期间无解析或文档修改、取消后的晚到结果被忽略及后续重试。文档基线在主窗口启动完成后建立，不混入启动初始化。

主窗口另通过实际分隔条手柄拖动调整比例并折叠两侧面板，检查布局状态同步、重新显示后的尺寸及当前页保留。夹具按控件最小尺寸保留可移动空间，并根据两侧可缩小的范围选择方向和距离，避免平台字体或较小窗口使输入被正常限位。分离窗口再次打开沿用关闭前的位置和大小，复用已有按钮流程，不建立屏幕尺寸或多屏组合矩阵。

原生编辑窗口按实际桌面空间放置，输入前等待激活。主题场景检查两侧时间轴的背景和刻度颜色随主题更新，并在切回后恢复。光标通知与合成拖动事件按顺序投递，矩形和区间选择使用可见区域中的位置，不依赖特定 DPI。

RHI 钢琴窗共用 fixture 在输入返回后请求并等待新帧，移除逐处维护的旧帧计数，避免输入过程中完成的待处理帧让预览检查提前结束。锚点场景复用同曲线与跨曲线数据行，跨曲线提交检查源/目标节点、身份保留及撤销。

完整 RHI 钢琴窗通过时间轴、键盘和画布的滚轮事件检查两轴缩放及视口移动。轨道文件拖入在按住鼠标到达边缘时持续滚动，离开后停止。两者均验证浏览过程不修改文档或历史。原生桌面套件遇到意外消息框时记录文字并判定失败，随后关闭消息框，避免无人值守执行停在确认按钮上。

公开片段工作流使用复制返回的身份继续跨轨移动和左右裁边，检查源乐句保留、新音符身份、裁边只改变可见范围，以及按顺序撤销后的完整恢复。混合片段和参数保真的详细规则继续由既有领域场景承担。

标题栏文件弹层通过实际条目、子菜单和按钮验证打开、移除最近记录、当前工程保护、新建及取消文件选择。键盘输入探针按作用域安装和释放，在原滑奏用例之外复用到完整钢琴窗，检查音区同步后的实际 MIDI 音高和滚轮对视口的影响。

文件日志在 Foundation 程序的独立子进程内执行，检查目录切换、拒绝无效目录、文件打开失败后的继续输出及恢复、第三方标准错误接收和旧日志清理。进程退出关闭全局日志句柄，临时目录与父进程的日志状态相互隔离。

MIDI/DSPX 批量工作流直接复用公开预检结果和生产批量入口，合并验证仅验证、取消重试、失败策略和全部失败的行为。包刷新检查失效目录、损坏声库与有效声库并存，以及提交拒绝和恢复。由于上游刷新会发布共享推理会话，提交准入必须先于该调用，拒绝时应用目录和推理会话均保持不变，受理后进入提交阶段。同一目录刷新 fixture 在生产提交门处暂停领先请求，验证后续请求等待成功刷新并复用结果，或在领先提交被拒绝后重新扫描，两种情况均只发布一次有效目录结果。刷新适配传递上游完整结果，保留独立于有效包快照的错误诊断，快照本身不包含这些诊断，因此不再用它替代刷新结果。模型资源流程只在内置声库的临时副本中制造损坏声学或声码器模型，检查失败终态、未发布缓存和修复后的同进程重试导出。

单文件预检与加载共用原有工程素材，增加受理后取消、授权撤销、源文件替换和当前工程编辑的提交边界。保留已有正常导入与打开断言。DSPX 写入另检查序列化拒绝时旧文件不变，以及修正后保存、重开恢复。JSON 校验器采用共用数据行检查有效值、错误码及 JSON Pointer 定位，不展开具体工具字段矩阵。

应用和 Qt 基础控件的中文翻译由 Qt CMake 的翻译合并功能生成同一内嵌资源，语言管理器只维护一个翻译器，部署后不依赖开发机的 Qt 翻译目录。已有语言切换场景同时检查应用菜单与 Qt 标准按钮的翻译，以及切回英文后的恢复。

音频解析到解码通过真实控制器及小型 WAV 验证，测试观察实际创建任务的源快照和终态，不自行推进任务状态。级联重定位验证同名文件的内容身份，拒绝错误素材，恢复正确素材后完成解码且不重复改变已恢复的来源。

解码、加载时解析与级联重定位共用保存决策的等待场景，验证取消新建后继续写回、替换文档后丢弃结果。受控线程池屏障还复用于删除待解析音频所属轨道：确认取消终态和历史不变，再经撤销恢复片段身份及真实波形。保留原有运行中解码取消用例。

MIDI 导入复用下拉框和复选框输入设施：错误编码与 UTF-8 的切换更新歌词预览并保留轨道选择，通道分离开关重新解析同一文件后按最终选项导入音符，整次导入可撤销。编辑器自动化使用生产 AppContext 接线操作实际主窗口，检查参数配对、视口、焦点、量化及翻页状态，保留文档和历史。真实鼠标编辑仍由原有 GUI 用例验证。

实际执行也校正了测试对产品与 Qt 的预期：歌词后移保留手工读音和候选，自动读音由 G2P 重算，不作为跨音符搬移的持久数据。原场景继续检查有效读音、音素清理和撤销。offscreen 下 QWidget 鼠标移动仅改变游标，菜单悬停改经 QWindow 明确投递事件，继续验证真实菜单预览、取消和提交。这些修正没有改变生产编辑语义。

完整拖放归入 EditorInteraction，使用 minimal 的 Qt 拖放循环验证轨道排序及规则排序，保留取消、预览、一次提交和撤销。控制器测试复用真实 AppContext，删除测试自行定义的实例函数。EditorInteraction 与 NativeDesktop 每个测试进程只创建一个 GuiAppFixture。各用例通过 GuiDocumentFixture 重建文档、等待任务完成并释放临时素材，保持 G2P 单例与应用一致的进程生命周期。启动/销毁场景在同一测试程序的独立子进程中执行并检查退出结果。普通应用 GUI 继续采用 offscreen。两个无原生句柄的后端均使用 Fusion，避免进入 Windows 原生主题路径。

RHI 钢琴窗用例通过真实组件执行连续擦除、内联歌词/发音、Tab 导航、分割及右键目标定位。音高绘制、描摹和擦除检查预览不改模型、取消、局部提交和撤销，保留原始曲线与范围外数据。输入后的帧提交和重新点击命中用于检查界面恢复，未增加 GPU 像素基线。

RHI 轨道菜单的歌声和音频粘贴场景复用实际撤销记录，片段已经移除后仍可按历史保存的轨道与时间范围定位。定位继续提交帧，不修改工程、版本或历史，后续双击新建、撤销和后端回退流程沿用原断言，不另造历史焦点或新增测试程序。

既有 RHI 编辑流程增加锚点追加预览，检查悬停不修改模型及插值、实际追加后的端点插值和撤销恢复。音符与片段拖动中更新播放位置不翻页，编辑结束后可在有效时间范围内向前或向后跟随，翻页不产生编辑历史。

原生框选夹具在按下前同步系统游标，移动后检查选区预览，再等待真实帧提交并核对释放后的选择。失败记录保留有界的鼠标位置和按键状态，便于区分输入阶段与帧交付期间的变化。

RHI 音高调制加载内置或显式声库，经实际语言与推理任务取得音符基线，Escape 与右键取消共用同一预览、模型保留、事务释放和帧断言，随后验证局部调制和单次撤销。同一基音 fixture 通过片段改名及音符移动触发来源更新，旧选区不能继续提交，撤销更新后可重新选择和调制，编辑曲线始终保留。发音区域目标用例复用已有布局坐标，DrawNote 下左键点击只选择对应音符，不新建音符或修改版本与历史，继续检查原菜单目标。原生轨道使用生成的双声道 WAV，经过真实解码后裁边、跨轨移动，检查毫秒锚定、材料长度、命中与撤销。WAV 素材生成与设备播放用例共用小型 fixture。

轨道 RHI 的双指缩放接入已有滚轮、时间尺和轨道列表导航场景，验证两轴缩放、可见锚点及列表滚动同步，继续共用完整工程和历史断言。锚点误差换算为画布物理像素，避免用固定 tick 容差限制不同 DPI 和缩放比例。macOS 的应用 GUI 程序通过原生窗口执行相同用例，使用既有桌面互斥。Windows/Linux 继续使用 offscreen。

时间尺的循环区间编辑以左右端裁边两行共用原有定位、整体移动和 no-op 流程，检查预览期间工程与历史保留、单次提交、公开状态及逐步撤销。真实控件绘制同时验证启用时的区间背景和标记，以及禁用时保留标记而移除背景。图片只比较同一控件在本次运行中的状态，不维护跨平台截图基线。

钢琴窗辅助视图复用既有键盘场景，增加音素栏的水平缩放与滚动接线。音素边界场景先检查缩放过低时的输入保护，再恢复倍率执行原有边界编辑和撤销，不另建重复的音符或声库夹具。

主窗口工作区场景通过正式播放定位与自动翻页入口检查实际钢琴窗。关闭跟随时视口保留，开启后分别验证跨一页、远距离和向后定位。片段长度在准备阶段设为能容纳这些位置的范围，避免把场景边界限制误当作定位失败。播放位置和原设置按作用域恢复，视图变化不修改工程、版本或历史。

参数锚点菜单使用有界的执行状态区分弹出菜单引发的窗口失活与普通失活。菜单动作执行前保留目标选择，关闭菜单后恢复未提交编辑的取消处理。平台通知、实际菜单动作、模型修改及撤销在同一应用 GUI 场景验证。

路径列表处理外部目录后不再交给仅处理内部移动的基类覆盖结果，并明确返回复制引用，保留内部排序的原有 Qt 路径。未限制扩展名的文件选择框也先验证本地 URL，避免远程地址变成空文件路径。组件套件通过真实拖入、列表选择、排序与删除验证这些行为。模拟拖动沿用 Qt 原生流程的已接受动作状态。

## 4. 跨平台与资源条件

LibreSVIP 接线在现有应用工作流中执行：测试程序的独立子入口代替外部转换器，接收正式命令参数和默认回答并返回预制 DSPX 内容，生产侧继续完成解析、格式计划和异步导入。失败输出也经实际进程传回。该替身不实现第三方格式转换，不把外部工具自身的兼容性计入已验证范围。

单文件导入还复用同一计划与素材，在受理后让转换进程失败，检查任务错误、原工程及历史保留。恢复转换器后在同一进程重试，沿用成功导入的内容和撤销断言。

音频任务共用 `ThreadPoolBarrier` 控制线程池调度，原路径解析和文档决策用例复用同一实现。批量导入的取消场景增加哈希完成、解码待执行的阶段，取消和重试均沿用完整工程、历史及撤销断言。

`lite_register_test` 集中配置测试类别、offscreen、原生桌面条件、资源条件和 Windows 动态库路径。通用测试不依赖 CI 环境变量，不无条件指定 Windows Qt 插件。原生桌面用例保留必要互斥。常规 Windows/MSVC 测试不要求覆盖率工具。

`ProcessFixture` 为场景分配数据根、配置、访问根和素材，只管理自身创建的进程与文件。成功清理，失败保留参数、退出状态、协议记录和 stdout/stderr。配置、日志、缓存和单实例身份复用统一数据路径，`DSEL_TEST_DATA_ROOT` 仅在测试构建生效，不扩展产品 CLI 或公开工具。

单实例服务在开始监听之前注册接入回调，并在接入时读取已有首帧。这样同时覆盖 Windows 监听期间同步发出的连接通知和后续异步通知。启动连接用例使用真实本地通道与并发客户端，检查主线程尚未处理请求时的 ACK，以及处理器安装后的单次分发。

可执行文件路径来自 CMake target，stdio 阻塞接收端采用跨平台替身。重启进程使用独立输出文件，并具备各平台的存活、所有权和清理实现。Qt Test 的 Windows 日志进入可捕获输出，资源跳过与失败细节可以汇总。

Connector 的本地服务名使用短 UUID 名称，失败时输出实际系统错误，避免 macOS 临时目录与场景描述共同超过 Unix socket 路径长度。连续滚动用例显式指定触摸板设备，使事件身份与预期手势一致。macOS 应用部署保留 FFmpeg 端口的私有相对路径，在 Qt 部署前复制对应配置的私有库目录，实际进程测试负责验证应用装配。

普通进程场景在套件启动配置中显式使用 CPU、空声库搜索路径并关闭自动推理。资源与初始化失败场景提供自己的配置。通用进程设施原样写入调用者配置，不隐式覆盖这些条件。

macOS 的原生窗口效果只在 Cocoa 后端操作 NSView，offscreen 保留普通 Qt 窗口行为。独立可执行的运行时测试通过 `RuntimeResourcesFixture` 取得实际 Editor 的歌词配置，在 macOS 另取得 bundle 插件目录并优先加载同一 bundle 的 Frameworks。资源路径覆盖复用已有测试构建开关，正式产品不识别该测试环境。缺失或空的内置规则在初始化时报告失败，避免按测试程序位置寻找资源导致文件系统异常中止。

GUI 初始化在 offscreen 后端统一使用 Fusion 样式。WindowsVista 样式依赖真实原生窗口句柄，Qt 的原生主题路径不适用于 offscreen。实际 Windows 执行出现的 `OpenThemeData` 错误与该约束一致。样式选择收敛在 `AppEnvironment`，应用和测试共用同一初始化，原生桌面继续使用对应平台样式。

macOS 部署先放齐插件、语言资源及 FFmpeg 私有依赖。歌词配置、插件清单、模型和词典归入 bundle 的 Resources，原位置保留包内相对链接，以兼容第三方插件的相邻资源布局，避免签名工具将数据当成代码。FFmpeg 私有库保留原有相对依赖，由应用的构建搜索路径声明私有目录，使 Qt 能通过 SONAME 链接解析库的版本化 install ID。预编译库不额外增加加载命令。随后由 Qt 官方工具统一处理依赖和签名。插件作为附加二进制提供，使其依赖相对自身位置解析，结束后检查完整签名。旧的手工 Qt 路径修补脚本已移除。

仓库内置 `voicebank-fixture.zip`，由 CMake 解压到当前构建目录，ModelResources、ApplicationGui 和 ApplicationWorkflows 共用默认资源。不要求在运行测试时安装训练框架。包使用独立的 `ci-fixture` 身份、两条人工声线及中英文小型词典，八个自制 ONNX 计算图满足各生产阶段输入输出要求，输出低幅度确定性音频，不包含真实训练权重或特定真实声库主体信息。生成代码暂留忽略的 build 目录，资源说明见[README](../../../src/tests/resources/README.md)。

显式配置外部声库时覆盖默认资源。指定后的加载或执行失败报告失败，不回退内置包。Windows 曾使用本机真实声库完成 CPU 推理、声码器和 WAV 导出，补充真实模型兼容性证据。内置资源不需要播放设备，也不能替代 GPU、真实模型质量、实际设备播放和听感检查。GAME/RMVPE 不在本期扩展范围。

设备行为已提供条件用例：输出设备自动发现或按名称指定，使用静音素材检查实际缓冲配置、落盘及播放回调。MIDI 通过显式配置的专用回环检查生产输入与合成器的 note-on/off 结果。没有可用输出设备或未配置 MIDI 回环时逐例 QSKIP。指定条件或已枚举设备初始化、打开、执行失败报告 FAIL。用例只清理自身资源，不安装虚拟驱动，不建立硬件组合矩阵，配置方式见[测试计划](test-plan.md#3-运行条件)。

常规 Headless 与声库测试共用 Native HTTP 请求、超时及响应校验，补齐实际协议要求的响应类型协商。资源用例提供显式语言和任务作用域，并等待异步 G2P/分段完成后再启动手动推理。共同传输路径在无声库测试中也执行，避免资源客户端独自偏离接口要求。

MIDI 导入的拍号校验复用 `Timeline::isTimeSignatureProjectionValid`，消除旧分母白名单与编辑器实际支持范围的差异。已有轨道选择场景同时验证导入有效的 7/32 拍号和忽略拍号，两条路径均保留所选音符与歌词。

包目录测试集中到 `tst_package_catalog.cpp`，继续读取正式目录快照。内置声库副本覆盖首次加载、本地化回退和版本变更后的显示更新。同版本仅修改显示元数据时，上游目录指纹未识别变化，失败复现作为待决依赖问题保留，详见测试报告。

独立设置页共用 `OptionsPanelFixture` 打开实际侧栏条目，并补齐产品容器提供的主题样式根。通用设置与音频/MIDI 设置复用同一准备路径，原有键鼠输入、保存及重开检查在实际 QSS 下执行。滑块另外检查明暗主题切换后颜色同步且控制值保留。

## 5. CI 与覆盖率采集

CI 使用 Linux x64、Windows x64 和 macOS arm64 矩阵，runner 均采用 latest。每个平台分段完成环境、依赖、配置、完整构建、测试和产物收集。Linux 使用 `coverage` preset 和 `build/Coverage`，测试后由独立 Coverage 步骤生成报告。Windows/macOS 使用普通 Debug `tests` preset 和 `build/Tests`，不运行覆盖率采集器。面向 `main` 的 PR 更新及 `main` 推送触发验证。Qt、vcpkg 和依赖版本由 workflow、manifest 及 overlay 声明。统一依赖引导脚本按 triplet 执行，Windows 构建复用项目 DevShell wrapper。各平台独立保留结果，构建或测试失败均传播失败退出码并收集诊断材料。普通 GUI 使用 offscreen，原生桌面集合在 Linux 使用 Xvfb，在 Windows/macOS 使用原生桌面。

缓存限于 Qt 和 vcpkg 包，不复用整个 CMake 构建目录。vcpkg 缓存键关联 runner 镜像、Qt 和依赖声明，回退缓存仅提供候选包。每轮仍执行 install，由 ABI 决定复用或重建。镜像升级后的新 ABI 包可以写入新键，避免旧键精确命中阻止保存。失败构建使用独立 partial key 保存已完成包，完整成功缓存使用独立键。缓存哈希包含共享端口和项目覆盖端口，Talcs 补丁变化同样触发实际依赖核对。此前 wolf-midi 的临时覆盖已经在上游修复后移除。

Qt 和 vcpkg 缓存按平台及 triplet 隔离。验收分别核对依赖缓存未命中的完整安装路径，以及实际命中后仍执行 install、完整构建和规定测试的路径。Linux 另有依赖升级时复用兼容包并重建变化依赖的证据。逐平台结论见[测试报告](test-report.md#42-缓存路径)，不以删除缓存或命中提示代替完整执行结果。

Linux GCC/gcov 插桩由显式选项启用，独立 Coverage 步骤使用测试已产生的数据，gcovr 统计项目生产源码的行与分支覆盖，排除测试、第三方及生成文件。`merge-lines` 合并同一源码行的模板实例，既有数据重算的口径变化不计为新增命中。逻辑覆盖以接近或超过 90% 为方向，不设机械 CI 门槛，不为达标排除整目录或填充 Schema 断言，也不重复运行测试生成报告。HTML、JSON、CSV 进入 Linux CI 产物。逐文件 CSV 同时输出到日志，便于直接定位缺口。三平台均保留 JUnit、完整测试日志和环境信息，失败素材包含测试产物范围内的隐藏暂存文件。

Windows 按需本地分析保留独立 `coverage` preset 和 Visual Studio 原生静态插桩，构建时提供 PDB 与 `/PROFILE`，关闭与其不兼容的 Edit and Continue。采集器在执行前插桩，覆盖 Editor/Connector 子进程并恢复原二进制。项目脚本按源码文件和行合并多个程序中的重复统计。Windows 与 Linux 的编译代码、行映射不同，分别报告，不直接把百分比差值视为新增覆盖。Microsoft 输出中的占位分支比例不作为分支覆盖率。

建设中的 Windows 专项采样表明，实际采集耗时主要来自大型原生程序的静态插桩，相关证据继续保留。最终 Windows CI 采用普通 Debug 全量测试，不要求 Microsoft 覆盖率收集器。需要进一步分析时再运行本地采集。测试程序和异步任务自身的截止时间保持独立。

macOS 按需本地分析保留 LLVM 源码插桩入口，按进程及模块输出原始 profile，再合并为 HTML、LCOV、逐文件 CSV 和原生分支汇总。最终 macOS CI 使用普通 Debug 全量测试，不进行 LLVM 插桩。Windows/LLVM 共用生产源码过滤、CTest 程序发现和源码行去重逻辑，保留测试输出与实际退出码。建设中已取得的跨平台专项采样仍可用于分析缺口，其运行条件和计数由相应产物承载。

LLVM 正式 LCOV 导出不再启用 `-dump`：该诊断选项会把调试文本写入标准输出，与 LCOV 数据混合并导致解码失败。采集保留标准错误、输入对象清单和原始 profile，先前的逐函数诊断独立留在产物中。不通过忽略无效字节修补报告，也不把报告输出污染误记为原始覆盖数据丢失。

## 6. 取舍与文档边界

测试目标按组件依赖和执行环境划分，后续可按共享 fixture 和依赖收益继续调整，不要求维持当前数量。推理门控使用真实任务快照验证结果应用规则，实际模型输出交给资源用例。主观视觉、实际听感和设备组合不建立像素或硬件矩阵。

默认钢琴窗和轨道视图走 Legacy/QGraphicsView，真实输入用例覆盖默认路径。实验 RHI 钢琴窗及轨道的独立组件在 NativeDesktop 中使用 Qt Null 后端，经过实际音符绘制/移动/裁边、音高锚点插入与取消、片段跨轨拖动和裁边，检查预览、提交/取消、命中、撤销重做及帧提交。完整主窗口的主题切换保留应用建立的原生图形后端。这些用例不建立像素基线，也不宣称穷尽 GPU 着色器和图形驱动行为。

本期文档是实施与发布验收材料，覆盖率详细计数和逐次运行记录留在 [Actions](https://github.com/flutydeer/ds-editor-lite/actions/workflows/tests.yml) 产物中，不建设长期文档同步或自动生成机制。最终通过依据包括规定测试与 CI、真实审查问题的处理，以及 Codex bot 对受审版本的认可。动态审查状态和完成证据统一保留在 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187)。
