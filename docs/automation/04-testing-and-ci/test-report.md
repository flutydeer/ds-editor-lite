# 四期测试报告

## 1. 验收结论与证据

扩展后的测试集合已完成三平台完整构建和全部适用测试验证，包括普通与原生 GUI、公共接口与批量工作流、实际音频解码与导出、内置声库推理、Null RHI 输入及条件设备用例。Linux 独立 Coverage 步骤正常生成报告，Windows/macOS 使用普通 Debug 构建；资源条件不足的用例单独记录为跳过。Windows 本地另曾以实际 Qixuan 声库完成 CPU 手动推理、声码器与 WAV 导出。覆盖提升不等于所有逻辑已充分验证，剩余行为及本地验证限制分别见第 5 节和第 4 节。

本报告保留本期验收结论、实质问题及验证边界，适用至本期发布。具体受测版本、环境版本、用例数量、耗时、逐例结果和原始日志以 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187) 关联的 [Actions](https://github.com/flutydeer/ds-editor-lite/actions/workflows/tests.yml) 及产物为准，不在文档维护逐提交状态。执行入口见[测试计划](test-plan.md)，功能与测试对应关系见[覆盖矩阵](test-coverage-matrix.md)。

Qt Test 的行为/数据行与 CTest 程序注册分别报告，数量不作为体系约束。失败、跳过和平台不适用分别处理，不将未执行计作通过。

测试整合后，游标、主题、视图/撤销控制器、应用服务及推理输入各自复用所属套件与 fixture。旧布尔场景包装已迁为直接 Qt Test slot，数值断言输出实际与期望值，共享辅助保留调用位置和原容差；提前失败仍清理对象与环境。用例职责和原有效输入保留，不以减少程序数代替行为验收。

全树整理将相邻职责收拢到领域套件，旧行为 slot 和数据行均核对迁移去向；多文件套件只有一个 Qt Test 类和一次执行入口，跨 Host 场景归入进程套件。音频资产用例改用真实应用和解码控制器，移除用于满足链接的空实现。共享生产组件与后续补测都纳入完整产品构建，不以单独编译测试替代应用装配验证。

## 3. 实质故障与修复验证

以下按根因归纳建设中确认的问题；逐轮日志和修复讨论保留在 PR 与 CI 产物，不重复记录运行流水。

| 问题 | 根因及修复语义 | 验证方式 |
|---|---|---|
| Linux 依赖或编译失败 | Qt 安装模块及 Linux 开发包不完整；部分依赖缺少标准头文件，生产库存在未声明的 ICU/提取模块链接依赖。补齐环境，在所属生产库声明依赖，并采用 wolf-midi、synthrt 上游已修复端口，移除其临时覆盖 | 依赖完整安装、完整 Editor/Connector/测试构建及跨平台执行通过 |
| Linux 软件源索引校验失败 | runner 预置 Chrome 源返回的包索引与校验元数据不匹配，失败发生在项目依赖安装前 | 保留软件源错误材料；同代码已有完整 Linux 通过证据，复验继续使用正常依赖命令及完整构建测试流程 |
| 存量测试未构建或结果不可见 | 独立 wrapper 测试未进入聚合入口，Windows 无控制台时日志输出不可捕获 | 纳入统一构建注册和日志环境，完整测试可发现且逐例结果可追踪 |
| LLVM 正式 LCOV 无法按 UTF-8 解码 | `export -dump` 将逐函数调试文本写入标准输出，污染 LCOV 输出；原始 profile 仍完整 | 正式导出移除 `-dump`，保留标准错误、对象清单及原始 profile；不忽略解码错误，也不将该输出故障描述为业务映射丢失 |
| Windows CI 无法取得新版 Qt 元数据 | Qt 上游调整仓库布局，已发布的 aqt 尚不识别；固定到上游已合并修复的版本 | 实际取得 Qt 并通过依赖安装及项目配置 |
| macOS 编译缺少 Objective-C++ 配置及线程类型 | Apple 源文件未启用对应语言；所用标准库尚无 `std::jthread`。显式启用 Objective-C++，四个不使用停止令牌且已有显式回收的测试线程改用 `std::thread` | 保留同步屏障和显式 join；由 macOS 完整构建及并发行为测试验证 |
| 拆分生产组件后 moc 编译缺少完整类型 | 信号按值传递 PackageInfo，头文件原先依赖其他 moc 文件的间接包含 | 在声明所属头文件包含类型定义，共享组件和完整应用构建通过 |
| Connector 缓存用例受机器负载影响 | 将任意重复次数和无产品 SLA 的短耗时门槛当作正确性条件 | 改为验证内容稳定、同步响应和 ID 复用，以及分页缓存不重复请求、快照变化后恰好刷新；保留协议超时和停止期限 |
| macOS 终态任务仍占用后台许可 | 代码假定移动 `std::function` 后原回调为空，libc++ 可能仍保留捕获的许可；终态记录继续持有该资源 | 转移回调时显式清空原值，保留锁外调用；在既有生命周期用例中检查任务历史保留时捕获资源已释放 |
| macOS 应用启动缺少 FFmpeg 私有库 | 端口提供了 `@loader_path/ffmpeg-builds` 布局，但应用部署未复制私有目录；Qt 通过 SONAME 链接读取版本化 install ID 时，另需能在私有目录解析该路径。部分预编译库也没有增加加载命令的头部空间 | 在 Qt 部署前复制私有库，由自建应用声明私有目录搜索路径，保留预编译库已有相对依赖；实际 Editor 进程用例验证装配 |
| macOS 连续滚轮用例使用了鼠标身份 | 合成事件默认指向主鼠标设备，和预期的触摸板输入路径不符 | 为该用例显式提供触摸板设备，检查小数累积及反向滚动的精确结果 |
| Windows 无 GPU 时初始化失败后退出阻塞 | 外层设备检查早退绕过共享运行时的完成通知，包任务继续等待会话，退出等待后台任务 | 统一完成通知，外层返回及关闭操作均唤醒等待者；通过已有 CUDA 查询配置在本机重现失败及退出阻塞，修后检查包任务及时失败和正常退出；普通进程场景另显式使用 CPU |
| macOS 独立测试程序找不到实际插件 | 共享运行时默认按主 bundle 定位资源，而独立测试程序不是 bundle | 共用 fixture 从真实应用目标取得插件路径和 Frameworks 搜索路径；只在测试构建启用覆盖，缺少目录或加载失败仍按失败处理 |
| macOS offscreen GUI 启动崩溃 | 窗口效果将合成 winId 当成 Cocoa NSView 指针 | 原生效果明确限定 Cocoa 后端，由真实 GUI 进程验证 offscreen 启动和交互通信 |
| Windows offscreen 控件进入不适用的原生主题路径 | WindowsVista 样式需要真实窗口句柄，offscreen 不具备该条件，实际执行出现 `OpenThemeData` 失败；Qt 原生样式实现也明确依赖该条件 | `AppEnvironment` 在 offscreen 统一选择 Fusion，应用和测试共用初始化；原生桌面保留平台样式，由完整 GUI 集合复验 |
| macOS 插件没有经过完整部署处理 | SRT 插件在 Qt 部署之后复制，未参与该工具的依赖处理和签名 | 改为先放齐资源，再统一部署附加插件二进制并校验签名；移除旧手工路径修补 |
| macOS 签名把配置与模型当成代码 | 歌词 JSON 位于 MacOS 目录，插件清单、词典和模型与二进制混放；签名工具按代码目录递归处理 | 将非 Mach-O 文件归入 Resources，保留包内相对链接满足现有资源查找；完整签名检查和真实进程测试验证应用包布局 |
| 自动化接口遗漏已支持的编辑模式 | 参数 Shape/Scale 在输出转换中落回 Draw，音高调制同样缺少名称映射；输入契约也拒绝这些模式 | 补齐双向转换并复用输入/输出模式契约；现有 GUI 接口用例检查设置到达的真实枚举、查询读回及工程版本不变，旧实现先复现失败 |
| 测试脚本省略 preset 时无法执行 | Test 模式沿用构建默认值 `debug`，但不存在同名测试 preset；改为仅在 Test 模式且未显式指定时默认 `local`，保留显式选择和其他模式默认值 | 通过省略 preset 的真实执行与显式 preset 执行验证 |
| 快捷键测试没有经过真实输入路径 | fixture 未建立可见控件和真实焦点条件 | 建立 owner、焦点和事件路径，验证快捷键触发及状态变化 |
| 保存分支丢弃后 dirty 状态错误 | 保存点引用已销毁的 redo 条目，地址复用可能误认新条目为保存点 | 删除条目时同步使对应保存点失效；用例先复现，再验证新编辑分支和文件往返 |
| 歌词拆分重复前缀 | 空匹配与已有匹配的推进规则错误 | 修正规则推进，验证混合文字、规则优先级及文本保真 |
| 歌词后移测试误认自动读音为持久编辑 | 测试要求自动 original 随歌词搬移，而生产只携带手工读音，自动值由 G2P 重算 | 改查有效手工读音跟随源歌词，保留语言、候选、音素清理与撤销断言，检查选区变连音后清除手工读音和候选；不改变生产编辑语义 |
| 同一自定义规则再次 Apply 更换身份 | 新草稿未持有首次保存生成的 ID；Splitter 详情收集和 DTO 转换也遗漏已有 ID | 两类规则在草稿创建时分配稳定身份，详情编辑和转换继续保留；编辑/启停/重开检查 ID 不变，Tagger 检查错误正则不改已应用配置，已通过三平台完整集合 |
| 无输出驱动时打开音频设置访问空指针 | 设备列表刷新未处理 driver 初始化失败 | 单入口检查实际 driver/device，禁用依赖控件并保留普通设置；真实输入、关闭提交和重开用例已通过三平台完整集合，无设备时不跳过整页 |
| 合成预览更换采样率后衰减时长改变 | 采样率通知只重算 attack/release，遗漏以样本数保存的 decay | 补齐 decay 换算；受控回调检查实际包络时长、有效 PCM、停止归零与清理，尚不以此代替真实设备播放 |
| 公开导出配置无法在独立调用方复制 | 隐式复制操作在公开头实例化，私有共享数据类型尚不完整 | 在实现文件定义复制构造和赋值，保留共享/写时复制语义；预设更新与实际导出流程承接公开复制操作，完整构建和测试负责复验 |
| stdio 与重启 fixture 不可移植 | 硬编码 Windows 可执行后缀和 shell，非 Windows 进程所有权及清理缺失 | 使用 target 路径、跨平台接收端和进程管理；替代进程独立输出，验证身份、就绪、退出和清理 |
| 公开播放请求因设备错误阻塞 | 按 QApplication 判断交互性，导致公开调用弹出模态错误框 | 仅 TrustedGui 显示设备提示；无设备公开请求返回错误，后续状态查询仍可完成 |
| 次实例及测试客户端可能误报发送失败 | `waitForBytesWritten` 的返回值不能单独说明数据是否已发送 | 按待发送字节判断等待条件，保留完整响应验证；连接、发送、接收和解码失败分别报告 |
| 退出请求在响应发送前断线 | HTTP worker 停止时直接销毁仍有待发送响应的连接 | 受控大响应先复现；改为有序断开、共享排空期限，再验证完整接收及客户端不读取时仍有界停止 |
| 普通音频导出后应用崩溃 | 恢复原先关闭的 premixer 时调用 `open(0,0)`，触发音频重采样断言 | Windows 确定性复现；按初始 isOpen 恢复关闭或原缓冲/采样率，打开与关闭数据行及真实进程导出均通过 |

| 公开语言查询与实际声库默认语言不一致 | 快照采集配置 getter，空语言被转为 unknown；接口另行解析优先级，与生产 effectiveDefaultLanguage 偏离 | 快照单独采集模型有效语言，查询、默认歌词、填词与音素路径复用；公开用例检查声线继承和独立选择、真实默认歌词插入及显式片段语言覆盖，保存数据和读取历史不被混用 |
| macOS 文件预览用例把同一文件的路径别名误判为不同目标 | 临时目录可能经过符号链接，授权文件层返回 canonical 路径；用例直接比较原始路径字符串 | 对已存在的同一文件比较 canonical 路径，保留选择、覆盖提示和原文件内容不变断言；三平台协议集合通过 |

| 关闭自动推理时手动请求停在声学等待状态 | 声学准入只考虑自动推理或播放，未保留本次显式请求 | 为目标流水线传递一次性许可，声学路径共用判断，Ready/取消时清除；受控生产状态验证后台等待、手动放行和完成后恢复，实际 CPU 模型输出通过 |
| LRC 时间缩放及失败重载状态错误 | 整秒和不同位数小数秒使用不一致换算，重载失败后遗留时长及读取位置 | 按实际时间单位解析，清空旧文档状态；LRC 数据行覆盖整秒、小数秒、多时间戳及失败后再加载 |
| 动态声线编辑改变未修改关键帧的身份 | 工作草稿重建关键帧时遗漏原 ID | 草稿保留已有身份，仅为新节点分配 ID；真实鼠标编辑和撤销检查位置、权重及身份 |
| 声库不可用时 DSPX 读回丢失声线来源 | 将尚未解析到的资源误判为无效来源并清除保存值 | 资源未解析时保留保存的来源；工程往返检查固定/动态混合和音素内容 |

macOS 的参数锚点菜单出现动作已触发、插值却未改变的问题。弹出菜单时的窗口失活通知调用了锚点取消逻辑，清空菜单所需的选择。Windows 发送相同通知可稳定复现；修复在菜单执行期间保留选择，菜单关闭后恢复正常失活取消。原用例继续检查真实悬停与 QAction 触发、模型修改和撤销，并验证菜单外失活仍丢弃未提交曲线。

## 4. 平台、资源与缓存验收

### 4.1. 平台和资源边界

Linux x64、Windows x64 和 macOS arm64 CI 分别完整构建 Editor、Connector 与测试，执行通用、协议、进程、GUI 及内置资源集合。Linux 使用独立覆盖构建，Tests 之后由 Coverage 步骤读取执行数据生成报告；Windows/macOS 使用 `build/Tests` 中的普通 Debug 构建执行全部适用测试。普通控件使用 offscreen；原生桌面集合在 Linux 使用 Xvfb，在 Windows/macOS 使用原生桌面。Windows 本地使用项目标准开发环境与构建/测试 preset，常规测试不要求覆盖率工具，也不以 CI 身份作为启用条件。Linux 的 RtMidi 在 manifest 中显式请求 ALSA；三平台依赖解析确认仅 Linux 引入该特性和依赖。

默认资源为仓库内置 `voicebank-fixture.zip`，由 CMake 解压。包采用自有身份、中英文小词典、两条人工声线和微型确定性 ONNX 图，经生产 G2P/S2P、Duration/Pitch/Variance/Acoustic/Vocoder 完成实际推理。中文用例使用 `啦` 验证 UTF-8 转换，英语用例使用 `la`；检查生成发音与音素、非静音 WAV、缓存复用，以及声线和 BPM 变化后的重算。素材不包含真实声库权重，运行测试不需要训练框架。

文件移除用例以实际文件共享能力为条件。Windows 本地已确认音频后端持有文件时删除被拒绝，明确记录 QSKIP；允许删除已打开文件的平台继续检查现有句柄完成解码、重新载入工程后识别 Missing 并丢弃旧波形。已打开句柄的读取不依赖目录项仍然存在，不把移除路径直接等同于当前读取失败。

ApplicationWorkflows 和 ApplicationGui 与资源程序共用该默认包。读音/音素工作流执行真实语言任务，验证编辑期间暂存、结束后应用，以及文档换代或片段删除后丢弃；这补充了未调度快照门控的接线覆盖，不要求播放设备，也不以任务受理代替完成。

ZIP 纳入 CMake 的重新配置依赖，复用构建目录时更新资源会触发重新解压；解压前仅清理专属的生成声库子目录，避免保留 ZIP 中已删除的内容，也不清理旁边的其他资源。独立 CMake 流程已验证仅执行 build 即可触发资源更新、清除陈旧条目并保留相邻文件。

`DSEL_TEST_VOICEBANK_ROOT` 可显式覆盖为本机真实声库，同时提供歌手、语言和歌词。配置失效时直接失败，不回退默认包。Windows 已有 Qixuan 真实模型执行证据：关闭自动推理后经 Native 手动请求、CPU 声码器及 WAV 导出，并以 libsndfile 检查采样率、声道、有限非零 PCM 和正常退出。真实模型及其本机路径不提交仓库。内置模型与真实模型的结果分别记录；CPU 成功不能替代 GPU、设备播放或主观听感，GAME/RMVPE 不在本期扩展范围。

NativeDesktop 新增输出设备与 MIDI 条件用例。输出设备自动探测或由 `DSEL_TEST_AUDIO_DRIVER` / `DSEL_TEST_AUDIO_DEVICE` 指定，静音素材用于验证配置落盘及真实播放回调；MIDI 由 `DSEL_TEST_MIDI_INPUT` / `DSEL_TEST_MIDI_OUTPUT` 指定专用回环，验证真实消息输入及生产合成器输出。无可用输出设备或未配置回环时逐例 QSKIP；已枚举设备或显式配置后的初始化、打开和执行失败为 FAIL。条件用例存在不代表设备环境已验证，执行情况由 Qt Test 逐例结果记录。

Windows 本地使用恢复后的 Visual Studio 2026 标准入口，已完成完整产品、测试构建、整套常规测试及原生覆盖率采集。依赖补丁通过 Dependencies 入口实际重建，再编译产品与测试；CMake configure 本身不替代依赖安装。后续扩展先定向验证与检查覆盖缺口，再完成规定集合；具体受测版本和逐例结果保存在本地产物与 PR，不将不同版本的结果混记。

本地覆盖采集曾在离线导出中复现片段范围修改与读取竞争；受控 PCM 读源在旧库中明确复现更新未等待读取，互斥修复后通过。实际应用 fixture 又复现 SDL 延迟启动访问已释放线程，驱动生命周期和停止标记修复后，常规完整测试及原生覆盖采集均通过。失败材料仍保留，失败轮次的覆盖报告仅用于诊断。

内置声库参与的 RHI 调制与双声道音频裁边/移动均已在本地真实组件中验证。立即关闭运行时另复现已结束的初始化任务残留：调试堆栈与任务状态指向引擎销毁后失去清理回调。将清理连接绑定任务自身、正常 fixture 销毁前处理完成通知后，包含该场景的完整本地测试通过。持久化推理参数的失效会推进 revision，调制用例据此区分版本变化与用户单次撤销。

完整 RHI 轨道编辑器的菜单、选择、新建和文件拖入接线已通过本地原生集合。NativeDesktop 与 EditorInteraction 在 `initTestCase` 创建进程级环境和应用运行时，各用例重建文档及控件。原先逐例销毁运行时会永久关闭依赖库的 G2P 单例，后续用例发出驱动缺失警告；共享运行时后语言能力保持可用，启动/销毁验证改在独立子进程中执行。

独立子进程的断言通过后曾在 Qt Windows 平台退出时崩溃。原生调试确认未初始化的 ASIO 驱动析构也调用 CoUninitialize，提前释放 COM 并卸载 Windows.UI，随后 Qt 清理缓存访问已卸载对象。Talcs port 修正初始化与清理配对后，三个启动/销毁场景及完整本地集合均正常退出；保留原生 Qt 平台与原有断言。

声线列表补测复现自定义混合在打开对话框时被初始预设覆盖。保留已有来源和比例、统一新建混合的平均分配后，正反向排序、拖放取消、来源替换、标签/选项同步和接受后重开通过；既有预设保存、选择、删除及平均比例用例同时通过。

撤销定位经真实快捷键复现首轨片段和钢琴窗顶端音符边框越过场景顶部而导致的可见性误判。焦点范围改用对象主体后，离屏片段、隐藏面板和顶端音符均先定位、再撤销；重做恢复位置并正确显示，完整 GUI 及编辑器组件集合同步验证通过。

Linux Xvfb 的 RHI 完整钢琴窗用例在首次显示后、窗口激活事件完成前请求焦点，Windows/macOS 同一用例通过。将原有的激活和首帧等待移到焦点操作之前，保留窗口、焦点和帧断言，不增加超时或跳过；对应原生桌面集合先在 Windows 本地复验，Linux 结果由后续实际 Actions 产物确认。

损坏工程的打开失败和重试通过真实保存确认、错误提示及文件解析验证。首次完整本地运行发现应答器将加载进度窗口误认成错误提示；按实际保存按钮和消息窗口类型限定应答范围后，完整 GUI 集合通过。配置写入失败另验证运行时音量、声像和热插拔策略回滚，恢复配置路径后可正常重试保存。

没有初始化音频后端的隔离子进程又复现真实回滚缺陷：恢复空设备时提前返回，配置已撤销但运行时音量仍保留新值。先恢复独立控制状态，并按实际名称判断是否需要切换后端和设备后，该场景、已有后端的保存重试及驱动生命周期用例均在 Windows 通过；无需依赖 CI 的设备缺失才能验证。

进一步使用本机可用音频后端验证驱动切换失败，确认旧设备已经销毁而公共输出上下文仍返回其地址。Talcs port 在销毁前同步清空公开引用后，释放、失败状态和后续初始化均通过；完整原生桌面及 GUI 集合一起复验。没有可初始化设备的平台在父用例报告跳过，不把子进程中的资源缺失计为通过。

MIDI 文件补测复现非零片段起点被加算两次的问题。导出统一使用局部音符位置与标准 DSPX 片段时间，同时在生成中间数据后落实元数据开关，避免转换器自动补入默认速度和拍号。重新解析实际文件检查原始和裁剪片段的音符、Unicode 文本及可选事件，修复后所属文档集合通过；DSPX 音素互操作另外验证外部修改与旧私有快照的优先级。

macOS 的批量 MIDI 导入用例暴露字符集名称大小写假设：CoreFoundation 与 ICU 提供的标识表示不同，大小写敏感查找无法选中 UTF-8。批量和单文件导入用例统一使用不区分大小写的语义选择，保留实际下拉操作、歌词保真和时间线断言；Windows 对应导入用例先通过复验，macOS 继续由实际 Actions 验证。

真实拖放另复现 Splitter 丢失未应用正则编辑，保存详情后规则优先级、落盘与重开验证通过。动态声线导航复现片段位于工程中段时无法跳到下一关键帧，时间换算修复后播放位置与视口验证通过；区间/菜单删除、首帧保护和旁路/停止流程在同一应用 GUI 套件验证。

建设中的 Windows 专项采样显示，前置静态插桩耗时显著高于测试运行，也存在插桩正常完成后测试自身失败的情况。原日志及结果继续有效，分析时分别核对插桩完成、CTest 退出及报告生成。最终 Windows/macOS CI 采用普通 Debug 全量测试；原生和 LLVM 采集器保留为按需本地工具。单个测试及任务超时不因采集耗时放宽，CI 最终结果按三平台全部适用测试及 Linux Coverage 步骤验收。

完整构建验证采用 Debug 测试配置，不代替 Release 安装包验收。测试成功清理自身沙箱；失败保留进程日志、退出状态和必要素材，包括隐藏导出暂存文件。

### 4.2. 缓存路径

以下保留建设中已经取得的缓存路径证据。测试集合或依赖扩展后的最终验收，仍以相应完整运行结果为准，不由历史缓存命中记录替代。

| 平台 / 路径 | 已有实际验收依据 | 结论 |
|---|---|---|
| Linux 冷缓存 | Qt、vcpkg 精确键及回退键均未命中，依赖完整安装后完成产品构建、规定测试和 GCC 覆盖采集 | 冷路径通过 |
| Linux 暖缓存 | 实际命中本平台缓存，仍执行 install，再完成完整构建、规定测试和 GCC 覆盖采集 | 暖路径通过 |
| Windows 冷缓存 | Qt、vcpkg 精确键及回退键均未命中，依赖完整安装后完成产品构建与规定测试 | 冷路径通过 |
| Windows 暖缓存 | 实际命中本平台缓存，仍执行 install，再完成完整产品构建与规定测试 | 暖路径通过 |
| macOS 冷缓存 | Qt、vcpkg 精确键及回退键均未命中，依赖完整安装后完成产品部署、严格签名检查与规定测试 | 冷路径通过 |
| macOS 暖缓存 | 实际命中本平台缓存，仍执行 install，再完成完整产品部署与规定测试 | 暖路径通过 |
| Linux 依赖升级 | 从旧缓存回退恢复兼容包，变化的依赖重新构建并形成新缓存；更新后的依赖再完成完整验证 | 升级后的复用与重建路径通过 |

缓存键关联 runner 镜像、Qt、依赖声明、共享端口及项目覆盖端口，实际复用由 vcpkg ABI 判断。缓存不决定依赖版本，也不跳过 install；清除缓存或出现命中提示本身均不作为完整验收依据。依赖升级及项目补丁必须经过实际依赖核对和完整测试。当前 CI 的缓存验收对应 Linux 覆盖构建及 Windows/macOS 普通 Debug 构建；macOS 部署与签名属于完整构建步骤，不以插件复制成功替代进程测试通过。

## 5. 覆盖率与补测选择

### 5.1. 统计口径

Linux CI 使用 GCC/gcov 和 gcovr 对已编译的项目生产源码采样，在独立 Coverage 步骤生成报告，覆盖应用、Connector、内部库及参与构建的工具代码，排除测试、第三方、生成代码和非目标编译器分支。报告复用 Tests 步骤的数据；Linux 未编译的平台实现不在分母内。

行统计启用 gcovr `merge-lines`，避免把不同模板实例的同一源码行重复计为多行。已用同一份既有原始数据核对 gcovr 合并结果与文件/行号去重结果一致；该口径修正与新增测试命中分别记账。完整报告不为了逻辑覆盖目标额外排除仍有效的 GUI 或业务文件。

按需本地或专项采样时，Windows 使用独立 `coverage` 构建及 Visual Studio 原生静态插桩，包含测试启动的 Editor/Connector；macOS 使用 Clang/LLVM 源码插桩，按进程和模块写出 profile，生成 LCOV、HTML、逐文件 CSV 及原生分支汇总。这两种采集器继续保留，不属于最终 Windows/macOS CI 的规定步骤。采集器从 CTest 元数据发现当前可执行程序，排除重组前遗留文件；按生产源码文件和行号合并各程序/模块命中，不重复计算副本。Microsoft 导出格式中的占位分支比例不作为分支覆盖率。

Linux CI 测试与覆盖采样包含内置声库，Windows/macOS 普通测试同样执行内置资源流程。本地专项采样记录各自的资源条件，Windows 已有真实声库采样单独保留；不同编译器、平台和资源集合的百分比不直接比较。删除已经没有产品接线的旧设置页及 TrackSynthesizer 所引起的分母变化，不计为新增行为命中。

测试执行成功与采集成功分别核对。失败轮次只用于诊断；LLVM 报告 mapping/profile hash 不匹配时，保留标准错误、对象列表及原始 profile，必要的逐函数诊断与正式 LCOV 分开保存，不能通过忽略警告使遗漏函数悄然退出分母。正式导出不用会向标准输出写调试文本的 `-dump`；详细数值和该类诊断的处理证据留在 PR 与产物。

本期对 LLVM 警告逐函数核对，确认所报零哈希来自未使用内联函数的占位映射；手写业务函数的实际非零哈希映射仍在 LCOV 中，未保留的对应项为 Qt 宏生成方法。因此没有据此缩小生产源码范围、屏蔽警告或引入自定义修正系数。

应测逻辑以接近或超过 90% 为方向，覆盖率用于定位缺口，不作为机械发布门槛，也不表示产品工作流完成比例。缺口按行为和未覆盖源码解释，不靠整目录排除或 Schema 填充达到比例。采样分子、分母、目录和逐文件明细集中在 PR 与覆盖率产物，文档保留统计口径和补测理由。

### 5.2. 如何确定值得补测的缺口

先对照产品职责和关键流程，再检查覆盖产物与源码，优先补齐缺失的普通行为、重要副作用和失败恢复。低覆盖本身不足以证明需要新测试；已有用例触达的初始化代码也不能证明业务流程已验证。

| 确认的行为缺口 | 本期补测与处置 |
|---|---|
| 整片段剪贴板未实际进入参数复制逻辑 | 补曲线类型、片段范围、跨轨粘贴及一次撤销；轨道真实右键 Copy/Paste 检查悬停预览、Escape 清理与提交位置一致，复用同一生产准备逻辑 |
| 推理输入转换测试未进入结果应用门控 | 在真实任务快照和 Headless AppContext 中验证 Apply/Drop/Defer、相关输入变化、对象消失及冲突编辑 |
| 快照门控未验证语言任务的 pending/flush 接线 | 内置声库执行真实读音/音素任务，检查编辑期间暂存、结束后应用和换代/删除后的丢弃，后台结果不新增用户撤销步骤 |
| 完整推理输出未验证公开状态中的任务关联 | Registry/Host 发起真实任务，暂停 Pitch worker 后检查当前及后续阶段的任务关联、已完成阶段和其他片段的隔离，实际成功后不再报告活动任务；使用默认内置声库，无需设备 |
| 歌词规则缺少实际拆分结果检查 | 补混合文字、启用/优先级和空匹配，修复文本重复问题 |
| 新建音符用例未覆盖已有音符拖动 | 通过真实鼠标事件验证预览、提交、Escape 取消及撤销后的场景和模型 |
| 音频导出仅触达初始化 | 用小型生成 WAV 完成真实 Editor 导入、导出任务和解码检查，并补打开/关闭混音器状态恢复 |
| 工程往返和保存分支缺少关键状态断言 | 检查音符、编辑发音、参数及声线等内容保真，覆盖丢弃保存分支后的 dirty 状态 |

| 默认参数及轨道视图未进入鼠标提交路径 | 真实参数绘制、Shape/Scale 和基于真实推理基音的 Legacy 音高调制检查预览、范围外保留、一次提交、取消及撤销。片段拖动与轨道头部名称/静音/独奏检查模型和撤销同步，颜色菜单检查悬停不产生历史、取消恢复及点击提交 |
| 实际导出流程未覆盖配置及进度对话框 | 通过键盘和鼠标检查格式、采样率、来源与混音的文件计划及预览，取消后重开恢复原配置；复用小型 WAV，经真实 Export 按钮执行生产导出，检查可见完成状态、进度达到 100%、Close 关闭、任务已清理及进度窗口释放，工程和历史不被修改 |
| 外观设置页未经过真实用户输入 | 从侧栏打开页面，切换动画并输入时长倍率，检查内存、配置文件及重开结果；遵循即时保存行为，工程版本和历史不受影响 |
| 音频/MIDI 设置被笼统归为硬件依赖 | 无播放设备时仍通过真实输入验证增益/声像、生成器/包络及参考音高、关闭提交和重开；预览组件另以受控回调检查采样率换算与实际 PCM 启停，真实设备选择继续使用条件用例 |
| 声线混合对话框只覆盖底层数值逻辑 | 通过标签移除来源并拖动分隔线，检查权重、确认结果及取消后重开；预设和文档保持原状态 |

补测以原本应成立的产品行为为依据，实际执行已发现并推动多处生产修复。推理结果门控使用未调度的任务快照验证应用规则，队列重启使用受控真实 worker，完整模型输出由资源用例承担；所属完整集合按平台验证，受测版本和具体结果由对应产物记录，不同层不重复铺设业务矩阵，设备条件跳过项继续单独报告。

Windows 本地采样继续推动普通接线补测：主菜单量化与八度移动、音素重置相邻词确认、语言切换、两侧裁边、Graphics View 锚点创建与合并、声线列表拖放及重开、固定/动态混合继承、播放窗口推理调度，以及导出等待推理时取消后再次执行。公共接口另检查整段绘制/锚点曲线的输入转换和音素有效语言，不重复领域层完整矩阵。详细行为及用例引用集中在[覆盖矩阵](test-coverage-matrix.md)。

普通逻辑补测进一步覆盖 Legacy 音频和歌声片段裁边、表达式数值框菜单、主题加载失败后恢复、真实文档解析中取消/退出及提交前重新确认。音频批量预检验证无任务与无副作用，执行期间目标删除或文档换代时拒绝旧结果；真实解码任务在目标删除后取消，撤销后重新解码。外部解码器打开失败与缓存目录不可写使用可控资源条件，分别验证失败终态及恢复重试。Connector 的异常 JSON、重复 SSE、非协议内容和兼容会话过期均进入生产传输处理，不增加工具字段镜像；MIDI 格式检查的素材包含轨道名称与歌词，检查实际预览及源文件变化后的计划失效。

Windows 的音频后端未开放文件删除共享，因此“保留打开句柄时移除素材”和“解码前源文件消失”按实际删除能力报告条件跳过，Unix 平台执行相应删除路径；解码器不可用、目标删除取消与恢复用例不依赖该条件。

真实音高编辑同步触发的下游曲线失效重置也会推进 revision，单次用户手势不等于固定的全局版本增量。该 GUI 场景检查一次提交信号、一次 Undo 恢复完整编辑曲线且历史为空，保留预览、取消、范围和实际基音验证；真实状态机收敛后检查同文档及版本推进，精确单命令增量继续由同步参数领域用例验证。

默认编辑器使用 Legacy/QGraphicsView，其真实输入继续由 ApplicationGui 覆盖。NativeDesktop 的实验 RHI 钢琴窗及轨道使用 Qt Null 后端，检查音符绘制/移动/裁边、音高锚点插入与取消、片段跨轨拖动和裁边的预览、提交/取消、命中、撤销重做和帧提交。这验证 CPU 准备与命令路径，不代表 GPU 着色器或图形驱动已经验证；几何和字形测试也不替代这些边界。

| 辅助界面与外部模型 | Tagger 编辑/Apply/无效正则、规则列表实际拖放及 LogWindow 接收/过滤/复制/清空已有补测；DeveloperPage 的渲染器选择验证配置持久化、稍后重启及页面重开。内置微型声库不覆盖 GAME/RMVPE、GPU、大模型组合或主观音质 |
| 无当前产品入口的遗留实现 | 旧全局 SeekBar、固定为 Classic 的键盘中残留的 Uniform 路径、公开协议已拒绝的旧片段草稿字段单独识别；源码保留，不为覆盖率添加绕过产品入口的测试 |

这些缺口继续按逻辑行为补齐，优先真实输入、状态变化和失败恢复；设备场景即使 CI 不具备条件，也应有可按条件执行的测试。纯声明、纯布局及约定不测范围与尚缺测试的逻辑分开说明，不通过排除有效源码、复述 Schema、工具清单或 getter 来提高比例，也不扩展设备及像素矩阵。逻辑覆盖以接近或超过 90% 为方向目标，未达到时报告具体剩余行为和原因；跨平台验收仍以各平台规定集合的实际结果为准。

## 6. 审查与发布完成依据

最终完成依据为三平台全部适用测试及 Linux 独立 Coverage 步骤通过、真实审查问题已修复并完成回复与解决，以及 Codex bot 对受审版本给出 thumbs-up 或明确未发现问题。Windows/macOS 按需本地采集不作为每次 CI 的必需步骤。代码或构建/测试配置在审查后变化时按执行计划复验，由仓库配置智能判断和触发审查。
