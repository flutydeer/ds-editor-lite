# 四期测试报告

## 1. 验收结论与证据

本期已完成测试职责重组、普通逻辑和真实 GUI 工作流补测、三平台 CI 调试及真实审查问题闭环。Windows 完整环境在约定业务边界内达到 90% 行覆盖参考目标，Linux、Windows、macOS 的规定 CI 集合通过。Linux 独立生成覆盖报告，Windows/macOS CI 执行普通 Debug 测试。

该结论针对已验证的产品代码。提交、运行链接、精确计数、逐例跳过原因和 bot 认可保留在 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187) 及其运行产物，正文不维护每次提交都需刷新的状态快照。纯文档整理复用对应代码的既有证据，不暗示重新运行了产品验证。

| 证据位置 | 用途 |
|---|---|
| PR 的 Checks、审查讨论及 reaction | 定位受审代码、三平台运行、真实问题处理和 bot 认可 |
| Actions artifacts | 环境、依赖/构建日志、CTest/JUnit、失败素材，Linux HTML/JSON/CSV 覆盖结果 |
| 本地 build/test-results | Windows 常规与插桩结果、原始覆盖文件、源码行汇总、业务边界区间、版本及差异分析 |
| 本地构建和采集日志 | 区分构建、插桩、测试、报告及最终清理的退出状态 |

目标是有意义的行为覆盖，不是所有平台的原始行比例都达到 90%。Linux 不具备本地全部设备条件，编译器记录的可执行行也不同，其结果独立解释。确认的剩余条件和依赖问题见第 6 节。

## 3. 实质问题的验证闭环

### 3.1. 产品缺陷

生产修复清单及原问题/新行为见[实现报告](implementation-report.md#3-生产问题修复与行为变化)。本表说明验证如何确认修复，不重复全部实现细节。

| 问题组 | 复现及修复后的关键证据 |
|---|---|
| 文档、历史和转移保真 | 保存分支丢弃、文档换代残留选择、整片段参数遗漏、损坏参数组和位置溢出均通过实际入口复现。完整快照、原子拒绝、Undo/Redo 和后续继续编辑共同验证 |
| 音频来源及格式 | 搬迁工程、批量不同来源、粘贴、重链接撤销和另存重开验证同一来源信息全程保留。真实解码确认正确素材，MIDI 重新解析确认局部时间与可选元数据 |
| 推理与线程 | 真实 worker 在运行、已结束及通知排队阶段受控取消/替换，检查无晚到写回、队列继续、许可释放及任务终态。初始化等待与单例并发另用生产组件验证 |
| 缓存与模型失败 | 微型声库执行各阶段，错误 ONNX 在加载成功后实际执行失败。损坏缓存、写出失败和旧探测结果不得发布，恢复资源后同进程成功重试 |
| 播放与上游音频 | 使用正式 mixer 输出及再解码验证循环、位置、静音和声像，检查离线导出恢复原状态。驱动生命周期用实际驱动子进程验证，设备可用时再验证真实回调 |
| Legacy/RHI 视口与输入 | 零长度 DSPX 先复现无效倍率，同一钢琴窗再打开正常工程并点击音符。两种视口共用有限范围断言，真实手势验证预览、取消、单次提交及完整撤销 |
| 设置与界面生命周期 | 配置文件故障验证控件、运行值和落盘值一致，恢复后继续操作。窗口、菜单、任务进度和工具提示正常关闭并验证引用释放，不能只隐藏控件规避问题 |
| 协议与进程退出 | 实际请求验证音频路径提交前重新授权、任务可查取消、完整退出响应、断管错误和单实例 ACK。拒绝后继续成功请求，检查端口与进程资源释放 |

部分覆盖扩大只补充主分支已有功能的验证，例如外轨参考音符、联合音符边界及既有触控能力。不把这些补测，或主分支已经具备的依赖链接、Provider 回退，列为本 PR 新增产品修复。

### 3.2. CI、部署和测试设施

| 症状 / 根因 | 最终处理及验证 |
|---|---|
| Linux 开发依赖/模块不全，生产链接和平台类型错误 | 补齐 CI 环境和真实目标依赖，Windows 专用声明留在平台条件内。完整三平台产品构建与程序启动通过 |
| macOS 缺 FFmpeg 私有库、后复制的插件未部署、数据被当作代码签名 | 保留依赖布局，先准备插件再统一 Qt 部署，非二进制放入 Resources 并用包内相对链接兼容加载。严格签名检查和真实 Editor 进程通过 |
| 独立程序找不到应用插件/规则，非原生 winId 被当原生句柄 | RuntimeResourcesFixture 使用实际 Editor 资源。Cocoa 效果按 QPA 限定，offscreen/minimal 采用兼容样式，三平台完整 GUI 集合通过 |
| Windows 大型注册源码和无控制台日志不可捕获 | 在实际编译目录设置大型源码选项，统一测试日志环境，全部程序可发现、可构建并输出逐例结果 |
| 原生窗口未激活、系统事件覆盖合成拖动、活动弹窗销毁 | fixture 等待真实曝光/激活，使用正确窗口/设备坐标，关闭弹窗并恢复焦点后销毁。保留帧、命中、菜单及历史断言，没有伪造活动状态 |
| 长路径、最小尺寸及跟随系统主题使 fixture 前提失效 | 点击可见交集、按可移动空间拖分隔条、回滚测试选择明确主题。保留生产限制，相关定向及完整集合通过 |
| 插桩或慢调度放大惯性、双轻触和长按时序问题 | 区分 fixture 配送不正确与生产到期处理缺陷。前者正确构造真实事件序列，后者检查已有截止时间，不降低门槛或无限重跑 |
| macOS 终态回调继续持有许可，后台任务完成时崩溃 | 显式清空转移后的回调，完成信号在所属线程发布并排队消费。受控回归及完整三平台执行通过，原崩溃材料保留 |
| MSVC 原生采集临时目录清理失败 | 采集器使用输出目录内独立 TEMP/TMP，测试和采集器退出状态分别核对。失败采样保留诊断，最终完整采集退出成功 |
| LLVM mapping/profile 警告及不同模板行重复统计 | 逐函数核对零哈希占位与有效业务映射，保留原警告。gcovr merge-lines 与源码行去重核算一致，不靠忽略警告或修正系数提高覆盖 |

建设中出现过 QSaveFile 提交被拒绝访问，已改进底层错误信息并保留失败材料，未确定外部触发原因。后续完整验证通过不等于已确认并修复该根因，没有为此增加盲目重试。

## 4. 平台与缓存验收

### 4.1. 运行环境

Windows 本地使用 Visual Studio 2026 标准 wrapper，完成完整 Debug 构建、常规 CTest 和独立 MSVC 原生覆盖采集。三平台 CI 使用 latest runner、固定声明的 Qt/vcpkg 依赖，完整构建 Editor、Connector 和测试。macOS 额外核对 bundle 部署及签名，Linux 测试后独立生成报告。

内置声库在三个 CI 平台均执行。真实声库本地专项采样作为独立证据保留。GPU、音频设备、MIDI 回环、文件删除及原生后端按实际条件报告，程序成功不把内部 QSKIP 转为已执行。配置和跳过规则见[测试计划](test-plan.md#3-运行条件)。

Debug 完整构建和测试不替代 Release 安装包验收。主观音质、视觉一致性和硬件矩阵不由这些结果证明。

### 4.2. 缓存路径

| 平台 / 路径 | 实际验证内容 | 结论 |
|---|---|---|
| Linux 冷/暖缓存 | 无缓存完整准备，以及实际命中后仍执行 install，完成产品构建、测试和覆盖生成 | 两条路径通过 |
| Windows 冷/暖缓存 | 无缓存完整准备，以及实际命中后核对依赖，完成产品构建和测试 | 两条路径通过 |
| macOS 冷/暖缓存 | 无缓存完整准备，以及实际命中后核对依赖，完成构建、部署、签名及测试 | 两条路径通过 |
| Linux 依赖升级 | 旧缓存提供兼容包，变化依赖按 ABI 重建并保存新缓存，再执行完整验证 | 复用与重建路径通过 |

缓存键关联 runner 镜像、Qt、manifest、共享及项目端口，不决定依赖版本、不跳过 install、不缓存构建树。上述建设验收不代替后续受影响依赖的实际验证，单独出现缓存命中提示不等于产品通过。

## 5. 覆盖率与补测效率

### 5.1. 统计口径

原始报告保留所编译生产源码，排除测试、第三方及生成代码。GCC 使用 merge-lines，MSVC/LLVM 按文件和源码行合并同次采样中不同程序/模块的记录。测试集合与采集发现使用同一筛选，不混入旧程序。不合并不同平台或不同轮次以制造通过数字。

业务逻辑覆盖在原始结果之外单独核算，按具体文件/行区间记录边界理由，同时扣除该范围已覆盖和未覆盖行。纯 Schema 声明、元信息、固定布局、约定模型范围及无产品调用的旧实现见[测试大纲](test-outline.md#10-业务逻辑覆盖统计边界)。运行时校验、条件分支、实际 GUI 输入、失败恢复和活动 Legacy/RHI 都保留，资源缺失不自动缩小分母，未完成分类仍纳入。

最终验收以 Windows 完整环境业务覆盖达到 90% 为参考，Linux 单独报告并要求 CI 通过。原始比例不等于业务比例，也不等于工作流完成比例。MSVC 的占位分支比例不使用，LLVM 映射警告逐函数核对，不屏蔽有效范围。

产物同时保存纳入与排除计数、原始数据、tested-version、文件/行差异及执行事实。分母变化和新增命中分别分析，删除无调用旧代码、合并实现或重算统计不能全部计作新增测试贡献。

### 5.2. 补测与重构的取舍

- 先检查普通未覆盖逻辑及未命中行规模，再沿实际产品工作流补齐副作用和失败恢复。
- 共享复杂乐句、小型文件、完整历史回放和输入场景，用数据行覆盖不同依赖条件，避免每个问题新增程序。
- 参数校验、声线插值、视口约束、快照和生产组件共用实现，减少重复测试相同业务算法。
- GUI 验证真实输入和画面/控件状态，协议只验证转换与接线，进程只验证完整装配，不跨层复制全部矩阵。
- 数值增长必须对应行为证据，不为工具定义、无业务声明或不可达私有分支堆砌测试。
