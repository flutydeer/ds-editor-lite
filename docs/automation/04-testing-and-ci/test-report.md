# 四期测试报告

## 1. 验收结论与证据

本期已完成 Windows 本地 Debug 全量构建与测试，包含实际 Qixuan 声库的 CPU 推理和音频导出。Linux CI 的完整产品构建、规定集合及依赖冷缓存、暖缓存和升级缓存路径有实际通过证据。测试按六类职责组织，新增默认 GUI 交互、真实声线传播及推理生命周期行为均完成 Windows 验证；各受测版本对应的 Linux 验证与审查结论统一由 PR 关联。

本报告保留本期验收结论、实质问题及验证边界，适用至本期发布。具体受测版本、环境版本、用例数量、耗时、逐例结果和原始日志以 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187) 关联的 [Actions](https://github.com/flutydeer/ds-editor-lite/actions/workflows/tests.yml) 及产物为准，不在文档维护逐提交状态。执行入口见[测试计划](test-plan.md)，功能与测试对应关系见[覆盖矩阵](test-coverage-matrix.md)。

## 3. 实质故障与修复验证

以下按根因归纳建设中确认的问题；逐轮日志和修复讨论保留在 PR 与 CI 产物，不重复记录运行流水。

| 问题 | 根因及修复语义 | 验证方式 |
|---|---|---|
| Linux 依赖或编译失败 | Qt 安装模块及 Linux 开发包不完整；部分依赖缺少标准头文件，生产库存在未声明的 ICU/提取模块链接依赖。补齐环境，在所属生产库声明依赖，并采用上游已修复端口，移除临时覆盖 | 依赖从源码安装、完整 Editor/Connector/测试构建及跨平台执行通过 |
| 存量测试未构建或结果不可见 | 独立 wrapper 测试未进入聚合入口，Windows 无控制台时日志输出不可捕获 | 纳入统一构建注册和日志环境，完整测试可发现且逐例结果可追踪 |
| 测试脚本省略 preset 时无法执行 | Test 模式沿用构建默认值 `debug`，但不存在同名测试 preset；改为仅在 Test 模式且未显式指定时默认 `local`，保留显式选择和其他模式默认值 | 通过省略 preset 的真实执行与显式 preset 执行验证 |
| 快捷键测试没有经过真实输入路径 | fixture 未建立可见控件和真实焦点条件 | 建立 owner、焦点和事件路径，验证快捷键触发及状态变化 |
| 保存分支丢弃后 dirty 状态错误 | 保存点引用已销毁的 redo 条目，地址复用可能误认新条目为保存点 | 删除条目时同步使对应保存点失效；用例先复现，再验证新编辑分支和文件往返 |
| 歌词拆分重复前缀 | 空匹配与已有匹配的推进规则错误 | 修正规则推进，验证混合文字、规则优先级及文本保真 |
| stdio 与重启 fixture 不可移植 | 硬编码 Windows 可执行后缀和 shell，非 Windows 进程所有权及清理缺失 | 使用 target 路径、跨平台接收端和进程管理；替代进程独立输出，验证身份、就绪、退出和清理 |
| 公开播放请求因设备错误阻塞 | 按 QApplication 判断交互性，导致公开调用弹出模态错误框 | 仅 TrustedGui 显示设备提示；无设备公开请求返回错误，后续状态查询仍可完成 |
| 次实例及测试客户端可能误报发送失败 | `waitForBytesWritten` 的返回值不能单独说明数据是否已发送 | 按待发送字节判断等待条件，保留完整响应验证；连接、发送、接收和解码失败分别报告 |
| 退出请求在响应发送前断线 | HTTP worker 停止时直接销毁仍有待发送响应的连接 | 受控大响应先复现；改为有序断开、共享排空期限，再验证完整接收及客户端不读取时仍有界停止 |
| 普通音频导出后应用崩溃 | 恢复原先关闭的 premixer 时调用 `open(0,0)`，触发音频重采样断言 | Windows 确定性复现；按初始 isOpen 恢复关闭或原缓冲/采样率，打开与关闭数据行及真实进程导出均通过 |
| 真实声库流程未进入有效推理 | 资源客户端缺少响应类型协商，语言和任务作用域偏离实际接口，插入音符后也未等待异步 G2P/分段就绪 | 与普通 Headless 共用 Native 传输，使用明确语言及任务作用域，等待可观察模型目标后手动请求；实际声库流程通过 |
| 运行中重启推理后替换任务停在队列 | 旧流水线状态销毁导致完成接收者消失，运行任务完成后队列未清理 | 先通过既有取消路径为该片段任务安装清理，再销毁旧流水线；真实 worker 暂停重启用例先复现、修后验证替换任务终态与队列清理 |
| 关闭自动推理时手动请求停在声学等待状态 | 声学准入只考虑自动推理或播放，未保留本次显式请求 | 为目标流水线传递一次性许可，声学路径共用判断，Ready/取消时清除；受控生产状态验证后台等待、手动放行和完成后恢复，实际 CPU 模型输出通过 |

上述修复没有通过删除有效断言、沉默跳过或无依据扩大超时取得绿色结果。重启输出管道曾是排查线索，未将未经直接观测的信号原因当作已证实根因。

## 4. 平台、资源与缓存验收

### 4.1. 平台和资源边界

Windows 使用项目标准开发环境与 `tests` 构建入口，再执行 `ctest --preset local`；Linux CI 完整编译 Editor、Connector 和测试，执行通用、协议、进程及可用 offscreen 的界面集合。通用测试同样可在本地运行，不以 CI 身份或 Linux 平台作为启用条件。

本期 Windows 验收使用本机显式配置的 Qixuan 声库，实际加载 ONNX 模型，在关闭自动推理时经 Native 请求完成手动推理、CPU 声码器及 WAV 导出。结果经 libsndfile 解码，检查采样率、声道、有限样本、非零能量和正常退出。声库路径及模型不提交仓库，测试使用自身临时配置和缓存。

Linux CI 不选择真实声库集合；本地未配置时报告跳过，配置后的加载、推理或导出失败按失败报告。CPU 模型成功不代表 GPU、实际设备播放或主观听感已经验证。macOS 本期未实际运行；测试路径、进程和 Qt 接口保留平台适配。主观视觉效果与听感仍需人工检查。

完整构建验证采用 Debug 测试配置，不代替 Release 安装包验收。测试成功清理自身沙箱；失败保留进程日志、退出状态和必要素材，包括隐藏导出暂存文件。

### 4.2. 缓存路径

| 路径 | 实际验收依据 | 结论 |
|---|---|---|
| 冷缓存 | Qt、vcpkg 精确键及回退键均未命中，依赖从源码安装后完成完整构建、测试和覆盖率步骤 | 冷路径通过 |
| 暖缓存 | 相同依赖配置下确认 Qt 和 vcpkg 精确命中，仍执行 install，再完成完整构建、测试和覆盖率步骤 | 暖路径通过 |
| 依赖升级 | 从旧缓存回退恢复兼容包，变化的依赖重新构建并形成新缓存；更新后的依赖再完成冷暖验证 | 升级后的复用与重建路径通过 |

缓存键关联依赖声明，但实际复用由 vcpkg ABI 判断。缓存不决定依赖版本，也不跳过 install；清除缓存或出现命中提示本身均不作为完整验收依据。

## 5. 覆盖率与补测选择

### 5.1. 统计口径

Linux 使用 GCC/gcov 和 gcovr 对已编译的项目生产源码采样，覆盖应用、Connector、内部库及参与构建的工具代码，排除测试、第三方、生成代码和非目标编译器分支。Linux 未编译的平台实现不在分母内。

Windows 使用独立 `coverage` 构建及 Visual Studio 原生静态插桩，包含测试启动的 Editor/Connector。脚本按生产源码文件与行号，对各程序/模块的命中取 OR 后去重；不将重复编译副本重复计入分母，也不把导出格式中的占位分支比例当作分支覆盖率。同平台的无资源和含资源集合分别采样，实际执行成功与覆盖率采集结果分别核对，最终明细保留在 PR 与产物中。不同编译器、平台和资源集合的总百分比不直接比较。

本期较早一次成功 Linux 采样为**行覆盖率 49.3%、分支覆盖率 40.4%**。这项阶段观测早于后续默认 GUI 和真实声库补测，不作为最终覆盖数值或发布门槛，也不表示产品工作流完成比例。精确分母、目录与逐文件明细保留在覆盖率产物中；文档不随每次采样刷新。

### 5.2. 如何确定值得补测的缺口

先对照产品职责和关键流程，再检查覆盖产物与源码，优先补齐缺失的普通行为、重要副作用和失败恢复。低覆盖本身不足以证明需要新测试；已有用例触达的初始化代码也不能证明业务流程已验证。

| 确认的行为缺口 | 本期补测与处置 |
|---|---|
| 整片段剪贴板未实际进入参数复制逻辑 | 补曲线类型、片段范围、跨轨粘贴及一次撤销；GUI 控制器入口复用相同生产实现 |
| 推理输入转换测试未进入结果应用门控 | 在真实任务快照和 Headless AppContext 中验证 Apply/Drop/Defer、相关输入变化、对象消失及冲突编辑 |
| 歌词规则缺少实际拆分结果检查 | 补混合文字、启用/优先级和空匹配，修复文本重复问题 |
| 新建音符用例未覆盖已有音符拖动 | 通过真实鼠标事件验证预览、提交、Escape 取消及撤销后的场景和模型 |
| 音频导出仅触达初始化 | 用小型生成 WAV 完成真实 Editor 导入、导出任务和解码检查，并补打开/关闭混音器状态恢复 |
| 工程往返和保存分支缺少关键状态断言 | 检查音符、编辑发音、参数及声线等内容保真，覆盖丢弃保存分支后的 dirty 状态 |
| 声线继承被测试空 stub 遮蔽 | 改用真实轨道和 SingingClip，检查继承传播、独立声线隔离、切回继承及通知 |
| 默认参数及轨道视图未进入鼠标提交路径 | 在 ApplicationGui 通过真实参数绘制和片段拖动检查预览、提交、Escape 取消及撤销恢复，不复制领域业务矩阵 |
| 实际导出流程未覆盖配置对话框 | 通过键盘和鼠标检查格式、采样率、来源与混音的文件计划及可见预览，取消后重开恢复原配置且不写文件、不修改工程 |
| 受控服务不能验证真实模型装配 | 用显式声库完成 CPU 手动推理和导出，进一步确认并修复流水线替换及手动声学准入问题 |

补测后上述实现均取得实际执行证据，部分用例同时发现并修复生产缺陷。推理结果门控使用未调度的任务快照验证应用规则，队列重启使用受控真实 worker，完整模型输出由资源用例承担；不同层不重复铺设完整业务矩阵。

默认编辑器使用 Legacy/QGraphicsView；完整的 PianoRollRhiWidget/TracksRhiWidget 属于显式启用的实验后端。已有几何和字形测试不能证明这些控件的交互、绘制及失败回退已经通过。本期不扩展该实验后端，也不把普通 UI 的未覆盖路径一概解释为 RHI、资源或平台问题。

其余未覆盖部分仍包括普通 UI 和应用工作流，以及未运行的平台、设备或模型分支。后续改动应沿[覆盖矩阵](test-coverage-matrix.md)复核重要行为，不为提高百分比堆砌 getter、Schema 镜像、工具数量约束、像素基线或设备组合。

## 6. 审查与发布完成依据

最终完成依据为规定测试和实际 CI 通过、真实审查问题已修复并完成回复与解决，以及 Codex bot 对受审版本给出 thumbs-up 或明确未发现问题。代码或构建/测试配置在审查后变化时按执行计划复验并重新请求审查。

动态审查状态、问题处理记录和最终认可统一保留在 [PR #187](https://github.com/flutydeer/ds-editor-lite/pull/187)。文档不静态记录“等待 ready”或某轮审查状态，也不为复制最终 reaction 产生后续提交。
