# MIDI 与音频拖放导入分阶段实施方案
> 状态：🔵 进行中（Phase 1–3 已实现并提交：虚拟追加槽、文件分类器、批量 MIDI 解析；Phase 4 混合队列/统一历史、Phase 5 测试回归未完成；落点偏移 Open Question 待讨论，2026-08-05 暂缓决策）

## Summary

实现分为 5 个 Phase。先解决轨道窗口缺少“新建轨道落点”的基础问题，再建立无副作用的文件准备管线，随后接入批量 MIDI，最后完成混合批次、统一撤销和完整验证。

最终行为：

- 画布内拖放：从落点轨道开始，MIDI 有效轨道和音频共用游标，连续占用现有轨道，不足时新建。
- 底部虚拟追加槽：整个批次全部新建轨道。
- 画布外拖放：在工程末尾新建轨道；音频从当前播放位置开始。
- MIDI 保留源 tick；音频使用统一的落点 tick。
- 批次内成功内容形成一个历史项，失败文件跳过并汇总提示。

## Phase 1：虚拟追加槽与拖放落点基础

### Changes

- 轨道画布底部永久增加一条与普通轨道等高的虚拟追加槽，但不写入 `AppModel`。
- Legacy 场景高度和 RHI 纵向内容均使用 `trackCount + 1`，使轨道填满视口后仍可滚动到追加槽。
- `TrackListView` 增加禁用、不可选择、不可拖动的同步占位行；内部轨道排序、选择和计数全部排除该行。
- 保留现有 `trackIndexAt()` 仅命中真实轨道，新增拖放专用命中结果：

```cpp
struct TrackDropSlot {
    enum class Kind { ExistingTrack, Append };
    Kind kind;
    int trackIndex;
    int snappedTick;
};
```

- Legacy/RHI 同时实现拖入、移动、离开和放下事件，并提供轨道高亮、垂直时间线以及上下边缘自动滚动。
- 落在追加槽时返回 `Append`；落在真实轨道时返回对应索引。

### Acceptance

- 轨道未填满、刚好填满和超过视口时均可看到或滚动到追加槽。
- 左侧轨道列表与右侧画布始终纵向对齐。
- 零轨道工程仍有一个有效追加落点。
- 内部轨道排序不会选中、移动或计入虚拟行。

## Phase 2：文件分类与无副作用准备模型

### Public Interfaces

```cpp
enum class ExternalFileKind { Unsupported, Project, Midi, Audio };

struct FileImportDropTarget {
    QList<int> existingTrackIds;
    int audioStartTick = 0;
};

void requestImport(const QStringList &paths,
                   std::optional<FileImportDropTarget> target = std::nullopt);
```

### Changes

- 增加共享文件分类：
    - `.dspx` 为工程。
    - `.mid`、`.midi` 为 MIDI。
    - 音频扩展名从 `FormatManager::extensionHints()` 获取。
    - 拒绝目录、远程 URL、不存在或不可读文件。
- 建立 `PreparedImportItem` 变体，分别保存准备完成的 MIDI 轨道或音频，不在准备阶段修改模型。
- 音频准备复用现有格式管理器和解码逻辑，保存路径、workspace、`AudioInfoModel` 与真实毫秒时长。
- 将当前“选择文件并插入音频”拆成文件选择和路径导入两层，右键菜单与拖放共用准备逻辑。
- 单个音频失败只生成结构化错误，不立即修改历史或弹出分散的错误窗口。

### Acceptance

- 可以独立准备有效音频并得到完整剪辑数据。
- 损坏文件、伪装扩展名和不支持格式不会污染模型或历史。
- 当前右键插入音频行为保持不变。

## Phase 3：批量 MIDI 解析与公共配置

### Changes

- 将 `MidiConverter` 拆分为：
    - 解析 MIDI 到可复用中间数据。
    - 根据指定编码和导入选项生成轨道数据。
- 单文件打开和菜单导入继续复用拆分后的接口，避免维护两套转换实现。
- 批量 MIDI 先解析全部文件，再只显示一次公共配置弹窗：
    - 编码默认根据所有成功解析 MIDI 的歌词检测。
    - “导入曲速”和“导入拍号”默认未勾选，保持当前追加导入默认行为。
    - 固定分离 MIDI 通道。
    - 自动导入所有含音符轨道，空轨道跳过且不占用轨道。
- 公共编码应用到全部 MIDI。
- 曲速和拍号只取输入顺序中第一个成功解析的 MIDI，其余文件的时间线数据忽略。
- 取消公共配置弹窗取消整个批次，不产生历史记录。

### Acceptance

- 多个 MIDI 只出现一次配置弹窗。
- MIDI 文件内多通道被正确拆分，所有有效轨道按文件和轨道顺序输出。
- 第一个 MIDI 损坏时，使用下一个成功解析的 MIDI 作为时间线来源。
- 空 MIDI 或无音符 MIDI 被记为失败，但不阻止其他文件。

## Phase 4：混合队列、连续分轨与统一历史

### Changes

- 文档导入控制器按 `QMimeData::urls()` 顺序串行准备 MIDI 和音频，期间保持 busy。
- 画布真实轨道落点保存从目标轨道到末尾的稳定 track ID 快照；追加槽和画布外不提供现有轨道。
- 提交前为所有成功内容运行一个共享轨道游标：
    - 一个音频占一条轨道。
    - 每个有效 MIDI 轨道占一条轨道。
    - 优先消费拖放时已有轨道，耗尽后按顺序新建。
    - 失败文件或空 MIDI 不推进游标。
- 写入已有轨道时：
    - 只插入剪辑。
    - 保留名称、歌手、语言、颜色、增益、声像和混音配置。
- 新建 MIDI 轨道使用源轨道名称和默认导入语言；新建音频轨道使用文件基本名。
- MIDI 保留源绝对 tick；画布音频使用吸附 tick；画布外音频使用未吸附的播放 tick。
- 新增 `BatchImportActions`：
    - 先应用可选曲速和拍号。
    - 再按分配结果插入剪辑和新轨道。
    - 音频长度按最终时间线与真实毫秒时长计算。
    - 整个批次只记录一个“导入文件”历史项。
- 单文件失败后继续；结束时汇总“文件名 + 原因”。
- 进度阶段取消时停止剩余准备，并提交此前已经成功准备的内容。
- 提交时目标 track ID 已不存在，则对应内容失败，不自动转移到其他轨道。
- 提交后激活输入顺序中的第一个成功剪辑，并启动现有音频哈希与相对路径处理。

### Drop Routing

- 单个 `.dspx` 继续调用工程打开流程。
- `.dspx` 与 MIDI/音频混拖时拒绝整个批次。
- 文件菜单导入 MIDI 没有落点，因此全部在工程末尾新建轨道。
- 落在虚拟追加槽时 MIDI 和音频全部新建轨道，但仍使用画布横坐标提供的音频 tick。

## Phase 5：测试、回归与 GUI 验证

### Automated Tests

- 文件分类：大小写扩展名、远程 URL、目录、未知格式、工程与资源混拖。
- 虚拟追加槽：零轨道、未填满、填满、超出视口、纵向缩放和自动滚动。
- 连续分轨：多 MIDI、多音频、混合顺序、MIDI 内多轨、现有轨道不足。
- 轨道属性：写入已有轨道不改变轨道配置，新建轨道名称和语言正确。
- 时间位置：MIDI 原 tick、画布音频吸附 tick、画布外播放 tick。
- 失败处理：损坏 MIDI、损坏音频、目标轨道删除、部分取消、全部失败。
- 历史：一次撤销/重做完整恢复剪辑、新建轨道以及原曲速和拍号。
- Legacy/RHI 对相同坐标产生一致的 `TrackDropSlot`。

### Verification

- 使用 debug preset 构建测试和 `DsEditorLite`。
- 执行完整相关测试集。
- 使用 Windows 资源管理器分别验证单文件、批量、混合文件、虚拟追加槽和边缘自动滚动。
- 在 Legacy 与 RHI 后端各执行一次 GUI 冒烟测试。

## Assumptions

- 现有轨道仅指拖放瞬间已经存在的轨道，不包括本批次新建轨道。
- 多个音频共享同一开始 tick，不首尾串联。
- 导入内容允许与已有剪辑重叠。
- Phase 1 到 Phase 3 先建立基础能力；完整用户功能在 Phase 4 接通后启用。
## Open Questions：MIDI 导入落点偏移

**现状**：MIDI 导入保留源 tick（音符从 MIDI 原始 tick 开始，与光标/落点无关）。
**理由**：与导入的曲速/拍号时间线保持绝对一致（音符 tick 0 = 时间线 tick 0）。

**代价**：
- 落点无效：拖放到光标位置，内容却从 tick 0 开始，违背“放哪在哪”直觉。
- 批量导入多个 MIDI 全部从 tick 0 开始 → 互相重叠。
- 与音频行为不一致（音频使用统一落点 tick）。

**候选方案（整体平移）**：音符 + 曲速/拍号事件一起平移 Δ，相对关系保持，落点语义与音频统一：
- 打开 .mid 为新工程：Δ = 0。
- 菜单导入（Append）：Δ = 播放头/光标 tick。
- 画布内拖放：Δ = 落点 snappedTick。
- 画布外拖放：Δ = 播放位置。
