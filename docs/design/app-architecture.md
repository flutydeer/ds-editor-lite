# 应用架构与模块边界

## 启动与运行模式

[应用入口](../../src/app/main.cpp) 解析启动参数、协调单实例交接，并按运行模式创建 [`AppContext`](../../src/app/AppContext.cpp)。GUI 模式创建编辑器窗口。Headless 模式复用应用服务和工程流程，由相应的请求队列处理打开工程请求。单实例接管条件、请求账本及次实例反馈见[启动与单实例交接契约](startup-handoff-and-inference-decoupling-design.md)。

## 表示、命令与界面

- 工程模型持有轨道、剪辑与工程时间轴等数据。文件格式转换在持久化边界处理，编辑逻辑使用统一的模型表示。
- 控制层负责协调文档流程与编辑动作。动作定义编辑的提交和撤销边界。视图根据模型和运行状态更新，在用户操作时把编辑意图交给对应入口。
- GUI 与公开自动化接口共用应用服务处理支持的操作。对外接口的参数、权限和返回值见[自动化接口参考](../automation/openrpc.md)。
- 音频、推理等模块保留各自的工作和资源生命周期。后台工作通过快照读取输入，结果在结果接收端通过对应的生命周期和版本校验后应用。

## 构建边界

应用入口链接 `EditorRuntime`。运行时将应用装配和剩余应用代码与专门的应用组件、共用库连接起来。组件所属源文件和目标之间的实际依赖以[应用 CMake 定义](../../src/app/CMakeLists.txt)为准。

[共用库的 CMake 入口](../../src/libs/CMakeLists.txt)列出 `src/libs/` 下的构建单元。库对外暴露下层能力，由上层组合。需要应用策略的工作由应用层通过参数、回调或接口接入，避免共用库反向包含应用层头文件。
